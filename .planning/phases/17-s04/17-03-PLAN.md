<objective>
收口 auth provider、axios refresh 与显式 /login /403 guards
</objective>

<context>
Phase: 17 (s04) — Milestone: Admin 管理后台与后端多模块重构

S04 的 hardest boundary 是 auth lifecycle。这个任务把散落在 `authClient.ts` 里的 fetch + localStorage 逻辑拆成统一 auth seam：session store、auth API、axios http client、auth provider、独立 `LoginPage` / `ForbiddenPage`，并让 unauthenticated 路由去 `/login`，authenticated-but-unauthorized 路由去 `/403`。所有 protected requests 都必须走单一 refresh pipeline，refresh 失败时 fail closed 清空 session。
</context>

<must_haves>

- 登录流、shell bootstrap 与业务 API 共用同一个 session store / refresh pipeline，不再出现多份 auth truth。
- expired/invalid access token 触发单次 refresh replay；revoked refresh 或 malformed identity 响应 fail closed 到 `/login`；authz failure 明确走 `/403`。

</must_haves>
