# S01 Research — PostgreSQL 全迁 + PgVector + MinIO 基础设施

**Date:** 2026-04-20
**Depth:** Targeted — known technology (Spring Boot + PostgreSQL + Flyway), moderate integration scope (H2→PG migration + new services), one new dependency (MinIO).

## Requirement Coverage

| Req | Description | Role |
|---|---|---|
| R046 | H2 全迁 PostgreSQL + pgvector 扩展，Flyway 迁移适配，所有现有功能不回归 | **Primary owner** |

## Summary

当前项目使用 H2 作为数据库（`MODE=PostgreSQL` 模式），Spring Boot 3.4.4 + Flyway + JdbcTemplate + Spring AI 1.1.4。现有 7 个 Flyway 迁移（V3-V9），全部使用标准 SQL:2003 语法（`generated by default as identity`、`timestamp with time zone`、`constraint check`），与 PostgreSQL 完全兼容——不存在需要改写的 H2 专有语法。

迁移工作量的核心在三件事：

1. **依赖切换**：pom.xml 替换 h2→postgresql + 添加 flyway-database-postgresql + pgvector/MinIO 依赖
2. **配置切换**：application.yml driver-class-name 改 PostgreSQL + docker-compose 加 PostgreSQL/MinIO 服务
3. **测试切换**：16 个测试文件全部硬编码 `jdbc:h2:mem` URL，需要统一改用 Testcontainers PostgreSQL

风险最高的是测试迁移——每个测试类都在 `@SpringBootTest(properties = {...})` 中内联了 H2 URL，没有共享的 test application.yml。需要引入 Testcontainers + 共享基类或 `application-test.yml`。

## Recommendation

**分步执行，先保绿再加新：**

1. **先做 POM + 配置 + Flyway 迁移**——把运行时从 H2 切换到 PostgreSQL，确保 Flyway V3-V9 在真 PG 上无错误
2. **然后切换测试基础设施**——引入 Testcontainers PostgreSQL，创建共享 test 基类，批量修改 16 个测试类
3. **最后加 docker-compose 服务**——PostgreSQL（pgvector 扩展）+ MinIO 容器 + 环境变量注入
4. **新增 Flyway V10 迁移**——创建 pgvector extension + vector_store 表（为 S02 铺垫）

这个顺序确保每步可独立验证，且 Flyway 迁移在真 PG 上先验证后再改测试。

## Implementation Landscape

### Key Files

- `backend/pom.xml` — 当前有 `com.h2database:h2` (runtime) + `org.flywaydb:flyway-core`。需要：移除 H2、添加 `org.postgresql:postgresql` (runtime) + `org.flywaydb:flyway-database-postgresql` + `org.testcontainers:postgresql` (test) + `org.testcontainers:junit-jupiter` (test) + `io.minio:minio` + `org.springframework.ai:spring-ai-pgvector-store`
- `backend/src/main/resources/application.yml` — `spring.datasource.driver-class-name: org.h2.Driver` 需要改为 `org.postgresql.Driver`。默认 URL 改为 `jdbc:postgresql://localhost:5432/babytalk`。需添加 `spring.flyway.locations` 和新的 MinIO 配置属性块。Flyway 需要 `spring.flyway.clean-disabled: true`。
- `backend/src/main/resources/db/migration/V3__create_accounts_and_sync_tables.sql` — **无需改动**。`bigint generated by default as identity`、`create table if not exists`、`varchar`、`timestamp with time zone`、`constraint check` 全部是标准 PostgreSQL 语法。
- `backend/src/main/resources/db/migration/V4-V9` — **全部无需改动**。所有 DDL 语法兼容 PostgreSQL。
- `backend/src/main/resources/db/migration/V10__create_pgvector_and_minio_infra.sql` — **新建**。`CREATE EXTENSION IF NOT EXISTS vector`、`CREATE EXTENSION IF NOT EXISTS hstore`、`CREATE EXTENSION IF NOT EXISTS "uuid-ossp"` + vector_store 表 + HNSW 索引 + MinIO 元数据表（可选，存储 bucket/object_key/status）。
- `docker-compose.yml` — 当前只有 backend 服务 + H2 文件卷。需添加 `postgres` 服务（使用 `pgvector/pgvector:pg16` 镜像）和 `minio` 服务。Backend 环境变量改为 PostgreSQL JDBC URL。
- `backend/Dockerfile` — runtime 阶段可能不需要改动（JAR 包内已含 PG driver），但 `.data` 目录不再需要（H2 文件数据库目录）。可以保留目录用作临时文件。
- `deploy/helm/babytalk/values.yaml` — `secret.BABY_TALK_DB_URL` 默认值从空字符串改为 PostgreSQL 格式说明。添加 MinIO 相关配置。
- **16 个测试文件** — 每个都在 `@SpringBootTest(properties = {...})` 中硬编码 `jdbc:h2:mem:*;MODE=PostgreSQL;...`。策略：创建共享 `AbstractIntegrationTest` 基类 + `@Testcontainers` + `@DynamicPropertySource`，所有测试类继承并删除内联 datasource 属性。

### 现有 Flyway 迁移语法审计（已完成）

| 迁移 | 关键语法 | PostgreSQL 兼容性 |
|---|---|---|
| V3 | `create table if not exists`, `bigint generated by default as identity`, `varchar`, `timestamp with time zone`, `constraint check(...)` | ✅ 完全兼容 |
| V4 | 同上 + `boolean not null` | ✅ 完全兼容 |
| V5 | 同上 | ✅ 完全兼容 |
| V6 | 同上 | ✅ 完全兼容 |
| V7 | 同上 + `foreign key` references | ✅ 完全兼容 |
| V8 | `alter table ... drop constraint if exists` + `add constraint check(...)` | ✅ 完全兼容 |
| V9 | `alter table ... add column if not exists` | ✅ 完全兼容 |

**结论：V3-V9 零改动。**

### Build Order

1. **pom.xml 依赖切换** — 移除 H2、添加 PostgreSQL driver + flyway-database-postgresql。这是一切的基础。
2. **application.yml 配置切换** — driver + URL + username/password 默认值。
3. **docker-compose.yml 添加 PostgreSQL + MinIO** — 让开发者能 `docker-compose up` 拉起数据库。
4. **Flyway V10 新迁移** — pgvector extension + vector_store 表 + 知识宫殿基础表（为 S02 铺垫）。
5. **Testcontainers 测试基础设施** — 共享基类 + 批量迁移 16 个测试文件。
6. **MinIO 配置 bean** — MinioClient bean + application.yml 属性 + health check。
7. **验证全部测试通过** — `mvn verify` 绿灯。

### Verification Approach

```bash

# 1. 启动基础设施

docker-compose up -d postgres minio

# 2. 验证 Flyway 迁移

cd backend && ./mvnw flyway:info -Dflyway.url=jdbc:postgresql://localhost:5432/babytalk -Dflyway.user=babytalk -Dflyway.password=babytalk

# 3. 验证 pgvector 扩展可用

docker exec babytalk-postgres psql -U babytalk -c "SELECT extname FROM pg_extension WHERE extname='vector';"

# 4. 运行全部测试（Testcontainers 自动拉起 PG）

cd backend && ./mvnw verify

# 5. 验证 MinIO 健康

curl http://localhost:9000/minio/health/live

# 6. 验证 backend 启动

docker-compose up -d backend
curl http://localhost:8080/actuator/health
```

## Don't Hand-Roll

| Problem | Existing Solution | Why Use It |
|---------|------------------|------------|
| 测试数据库生命周期 | Testcontainers (`org.testcontainers:postgresql`) | 自动拉起/销毁真 PG 容器，不需要外部 DB 依赖。Spring Boot 3.4 原生支持 `@ServiceConnection` |
| pgvector 表/索引管理 | `spring-ai-starter-vector-store-pgvector` | 自动建 vector_store 表 + HNSW 索引，配合 `spring.ai.vectorstore.pgvector.initialize-schema=true` |
| PostgreSQL Flyway 支持 | `org.flywaydb:flyway-database-postgresql` | Spring Boot 3.4 + Flyway 10.x 需要此模块才能识别 PostgreSQL dialect |
| MinIO S3 客户端 | `io.minio:minio` | 官方 Java SDK，支持 S3 兼容 API。比手写 HTTP 调用可靠得多 |
| Chat Memory 持久化 | `spring-ai-starter-model-chat-memory-repository-jdbc` + `JdbcChatMemoryRepository` + `PostgresChatMemoryRepositoryDialect` | Spring AI 内置 JDBC chat memory，直接支持 PostgreSQL dialect。为 S04 铺路 |

## Constraints

- **Spring Boot 3.4.4 + Flyway 10.x**：Flyway 10 对数据库支持模块化，必须额外添加 `flyway-database-postgresql`，否则启动时报 `No database found to handle jdbc:postgresql`。
- **Spring AI 1.1.4 BOM**：所有 spring-ai 依赖版本由 BOM 管理，不要手动指定版本号。
- **pgvector/pgvector:pg16 Docker 镜像**：自带 pgvector 扩展，但需要在 SQL 中 `CREATE EXTENSION IF NOT EXISTS vector` 激活。
- **测试类全部使用 `@SpringBootTest` 全上下文加载**：没有 `@DataJdbcTest` 轻量级测试，切换 Testcontainers 需要统一处理 Spring context 共享（否则每个测试类启动一个 PG 容器，太慢）。应使用 `@Testcontainers` + singleton container 模式。
- **H2 依赖移除后不可保留 `scope:test`**：Decision D071 明确"不保留 H2"，测试也需要切换到真 PG。
- **MinIO 需要 access key / secret key**：docker-compose 环境变量注入，application.yml 需新增 `app.minio.*` 配置属性组。

## Common Pitfalls

- **Flyway 校验失败** — 如果本地已有 H2 文件数据库跑过 V3-V9，切换到 PG 后 Flyway history 表为空，会重新执行所有迁移。这是正确行为（全新 PG 实例），但不要在已有数据的 PG 实例上运行（会报 table already exists）。`create table if not exists` 已经处理了幂等性。
- **Testcontainers 容器共享** — 如果每个 `@SpringBootTest` 类各起一个 PG 容器，16 个测试类 = 16 个容器 = 启动极慢。使用 singleton container pattern（static `PostgreSQLContainer` + `@DynamicPropertySource`）+ Spring context caching 让所有测试共用一个容器。
- **`bigint generated by default as identity` vs `generated always as identity`** — 当前使用的是 `by default`，PG 完全支持。不要改成 `SERIAL`（语义不同）。
- **MinIO MINIO_ROOT_USER / MINIO_ROOT_PASSWORD** — MinIO 新版使用 `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` 环境变量，旧版的 `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` 已弃用。
- **pgvector 扩展权限** — Docker 容器中的 PostgreSQL 用户需要 superuser 权限才能 `CREATE EXTENSION`。`pgvector/pgvector:pg16` 默认的 `postgres` 用户有权限，但如果用自定义用户需确认。

## Open Risks

- **Testcontainers 在 Windows 环境下需要 Docker Desktop**：开发者如果没有 Docker Desktop 运行中，测试会失败。这是从 H2 in-memory 迁移到 Testcontainers 的代价。可以在 CI 中确保 Docker 可用。
- **MinIO 镜像拉取速度**：首次运行 docker-compose 需要拉取 `minio/minio` 和 `pgvector/pgvector:pg16` 镜像，在中国大陆可能较慢。
