## 2026-06-19 Interaction Engine Override

This plan is also controlled by `41-INTERACTION-ENGINE-CONTRACT.md`. Where older
text describes a controller that only loads fixed content or forbids all child
reaction input, this override controls:

- keep `RitualContentApi`/`RitualRoomRepository` for room bootstrap
- add `RitualInteractionApi`/`RitualInteractionRepository` for evolving turns
- add a typed `RitualContextInput` envelope with reaction, voice, free-text,
  future-signal, and strategy variants
- implement all five normalized input variants in the Phase 41 mock engine
- return immutable `RitualInteractionSnapshot` values with interaction ID,
  monotonic revision, accumulated context summary, strategy metadata, and one
  current `RitualUtteranceSuggestion`
- test at least two sequential context submissions
- keep voice/free-text/future-signal/strategy controls hidden in the Phase 41
  UI while testing those engine paths directly

Neutral input such as `还不想穿` or `想自己来` is allowed. Compliance,
correctness, learning, scoring, and persistent child behavior records remain
forbidden.

### 2026-06-17 Historical Product Correction

This plan must follow `41-SCHEMATIC-DESIGN.md`. Any older instruction in this file that starts the controller at First Entry, opens Today Orientation, or models Room Support as one fixed phrase is superseded.

Plan 02 now owns the backend-shaped Ritual content boundary and the complete
data-to-domain path required by `mobile_v2/CODING_STANDARDS.md`:

- `RitualContentApi` interface
- asynchronous `MockRitualContentApi` implementation
- transport-only `RitualRoomResponse` and action-beat DTOs
- `RitualRoomMapper`
- `RitualRoomRepository` and `RitualRoomRepositoryImpl`
- immutable `RitualRoomContent` and `RitualActionBeat` domain models
- optional immutable `RitualMemoryPrompt` and `ParentMemoryChoice` domain models
- loading, ready, and recoverable error/retry controller states
- one dedicated mock response JSON payload

It additionally owns the Interaction Engine path listed in the 2026-06-19
override. The content path bootstraps stable room material; the interaction path
advances context and must not be folded into a stateless content lookup.

The mock response contains:

- approved static parent-child line illustration metadata
- ritual title `Shoes on.`
- Chinese helper `穿鞋啦。`
- context label, body heading, and play-all label
- three D.4.3 action moments with minimum utterances, optional continuations,
  Chinese action helpers,
  and action / TPR cues
- play-all and per-beat audio metadata
- low-pressure reassurance
- quiet exit state `先这样就好`
- optional post-exit memory prompt/options supplied by the same API response

All ritual-specific content must come through the repository. Presentation must
not import DTOs, the mock API, or the JSON fixture. Tests must inject an alternate
repository or source response and verify that consumers observe the changed values.

The local controller supports direct `Ritual Room Support`, typed contextual
input, in-place interaction snapshot updates, and an optional post-exit Memory
Lens. It must not expose First Entry, Today Orientation, `nextPhrase`,
completion, progress, child compliance, or child performance state. A deployed
backend and AI generation remain out of scope, but both mock API contracts are
required and are not scope drift.
