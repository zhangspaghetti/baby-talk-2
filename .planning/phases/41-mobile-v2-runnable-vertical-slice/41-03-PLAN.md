## 2026-06-17 Product Correction Override

This plan must follow `41-SCHEMATIC-DESIGN.md`. It builds only the direct
repository-backed `RitualRoomScreen`; no per-ritual entry/orientation page or
pre-support CTA is part of Phase 41.

Plan 03 now owns the `mobile_v2` app shell plus the direct `Ritual Room Support` initial surface. Pumping the app should open `shoes_on_room_v1` support directly, with no per-ritual First Entry page, no Today Orientation page, no onboarding semantics, and no Home/dashboard semantics.

The screen is a projection of one evolving `RitualInteractionSnapshot`.
Reaction context is submitted without navigation and replaces the current
utterance in place. The app shell injects both the room-content repository and
interaction repository. Widgets must not reconstruct context history.

The screen composition must follow the approved D.4.5 prototype at
`.planning/phases/41-mobile-v2-runnable-vertical-slice/assets/prototypes/phase41-d4-5-interaction-engine.png`
and the linked contract in `41-SCHEMATIC-DESIGN.md`. If the prototype or static
illustration is missing, execution must stop.

`main.dart` is the composition root for demo mode: it creates both mock data
sources, their mappers/repositories, and the controller, then injects the
domain-facing dependency into `BabyTalkApp`. The app shell renders loading,
ready, context-submitting, and recoverable load/submit error/retry states.
Presentation must not import mock data sources, DTOs, JSON fixtures, or ritual
literals.

The focused widget test injects a fake repository and asserts the support surface
shows domain-provided ritual identity, one current complete utterance, one
action cue, audio label, neutral context input, reassurance, and quiet exit. A second domain payload with deliberately different
safe text must render those changed values, proving the UI is not hardcoded.
