## 2. 任务依赖关系

### 关键依赖
- BT2-01 完成后，才能并行启动 BT2-02、BT2-03、BT2-04。
- BT2-02 输出的审计清单是 BT2-05 和 BT2-06 的前置输入。
- BT2-04 与 BT2-05 完成后，才能稳定推进 BT2-06。
- BT2-06 完成后，再进入 BT2-07、BT2-08 的核心代码改造，避免 UI 先改、状态后补导致返工。
- BT2-07 与 BT2-08 基本定型后，才能完整落地 BT2-09、BT2-10、BT2-11。
- BT2-11、BT2-12、BT2-13、BT2-03、BT2-10 完成后，才能执行 BT2-14 的发布前总回归。

### 可并行任务
- BT2-03 可与 BT2-02、BT2-04 并行，尽早给后续重构提供护栏。
- BT2-07 与 BT2-08 可以在共享 IA 原则下并行推进。
- BT2-11 与 BT2-12 可以并行，一条线处理文案与语义，一条线处理错误状态与日志。
- BT2-13 可在 BT2-06 稳定后穿插执行，不必等所有 UX 改造完成。

## 5. 风险缓冲建议
1. 为 BT2-06、BT2-09、BT2-14 预留 20% 缓冲，这三项最容易暴露隐性问题。
2. 在第 2 周到第 5 周对 boot、home、practice、share 相关需求实行小范围 freeze，避免边迁移边新增 legacy 接线。
3. 每周固定一次产品、设计、技术三方评审，避免导航与首页改造出现方向反复。
4. 为导航改造和无障碍播报保留 feature flag 或回退方案，确保问题可局部止损。
5. quick integration pack 首轮只覆盖主路径，阈值采用阶段式抬升，防止一次性把 CI 压垮。
