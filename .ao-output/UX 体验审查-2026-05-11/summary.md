### Step 3/3: summary（UX 架构师）

# Baby Talk 2 Phase 1 UX 汇总审查报告

## 1. 总体体验评分

总体体验评分：**6.7 / 10**

分项评分：
- 核心价值清晰度：8.4
- 新手上手效率：7.3
- 信息架构清晰度：6.4
- 认知负荷控制：5.8
- 错误预防与恢复：7.6
- 无障碍成熟度：4.7

评分说明：
产品方向、场景选择和“先开口一句”的核心价值是成立的，且离线优先、本地保存、Mentor 辅助、花园成长这些设计有明确差异化。但当前系统把太多内部复杂性直接暴露给用户，首页和练习页承担了过多并列任务，同时动态交互层的无障碍能力尚未达到可发布门槛，因此总分被明显拉低。

## 2. 关键问题清单

### 高优先级

1. **核心路径被内部状态和并列任务稀释**  
首页、练习页和账号页暴露了过多系统态、说明态和重复入口，削弱“现在就说一句”的主任务聚焦。

2. **动态交互层无障碍缺口明显**  
Mentor FAB、C3 激活框、离线/流式响应、录音与播放状态、庆祝动画缺少系统级状态播报、焦点管理和减少动效策略，当前不能判定为 WCAG 2.1 AA 合规。

3. **全局浮层与导航边界不清**  
4-tab、Drawer、全局 Mentor FAB 的职责边界不够稳定，用户容易在 Home、Discover、Garden 之间重复判断“该从哪里继续练”。

4. **自动流与庆祝动效缺少可控性**  
Auto-Flow、展开/收缩、粒子庆祝等高动态内容没有明确的暂停、继续和系统减少动效适配。

### 中优先级

1. **术语体系不统一**  
用户文案、英文短语、工程内部命名在同一界面混杂，形成“半产品、半调试”的感知。

2. **练习页首屏信息密度过高**  
一句短语周围叠加过多机制和说明，抬高了第一次开口的心理负担。

3. **账号与同步入口分层不足**  
登录、同步、共享、撤回同意、删除账号等高低频动作集中呈现，增加理解成本和风险感。

4. **手动无障碍验证证据缺失**  
缺少 TalkBack、VoiceOver、键盘、缩放、高对比度、减少动效的真实验证结果。

### 低优先级

1. **成长反馈还不够“可感知”**  
成长页有记录，但还没有足够强的“持续练习为什么值得”的反馈闭环。

2. **部分系统层英文仍然侵入中文主界面**  
会在低注意力场景下放大理解成本。

## 3. 改进路线图

### 短期速赢（1 个迭代内）

1. 收起所有面向用户的工程态、调试态、内部枚举值，只保留任务导向文案。
2. 将首页首屏收缩为一个主 CTA：`继续今天这一句` 或 `开始今天这一句`。
3. 修正 Mentor FAB 的可访问名称，补全建议/聊天 tab 的选中态和面板焦点返回。
4. 建立统一状态播报层，覆盖离线、重连、录音、播放、失败、限流、完成等关键状态。
5. 为 Auto-Flow 与庆祝动画补暂停/继续和 `prefers-reduced-motion` 适配。
6. 统一本地化所有语义标签、hint、错误提示，移除界面中的英文无障碍标签。

### 中期优化（1-2 个迭代）

1. 重构 4 个主导航的职责边界：Home 负责继续、Discover 负责找内容、Garden 负责成长可视化、Growth 负责证据与记录。
2. 重排练习页首屏信息层级，只保留“短语、中文义、播放、宝宝反应、下一步”。
3. 将账号/同步页拆为多层：先登录同步，再做共享协作，再放高风险设置。
4. 为 Mentor、C3、花园、成长四条关键路径建立键盘导航和屏幕阅读器回归清单。
5. 完成深浅色模式下的对比度审计，以及系统大字号和 200% 缩放回归。

### 长期规划（持续建设）

1. 将 Mentor 从“常驻入口”升级为“情境辅助层”，按用户停顿、重复播放、失败次数动态增强帮助。
2. 将 Growth 从记录容器升级为动力系统，输出“本周说了几次”“哪个场景最自然”“宝宝最常见反应”等趋势反馈。
3. 建立统一的 UX 文案与状态语义规范，保证产品语言、设计系统和代码状态模型之间一一映射。
4. 将无障碍检查纳入发布门禁，形成自动化扫描 + 手动辅助技术实测的双轨流程。

## 4. 无障碍合规差距及修复优先级

当前结论：**尚不能判定为 WCAG 2.1 AA 合规，当前状态更接近“部分覆盖、未完成验证”。**

### P0 发布前必须修复

1. 动态状态可感知：离线、SSE 重连、TTS 就绪、ASR 失败、速率限制、完成反馈必须能被屏幕阅读器感知。
2. 弹层焦点管理：Drawer、Bottom Sheet、Mentor 面板、发现页弹层必须定义初始焦点、焦点约束和关闭返回。
3. 动效控制：Auto-Flow、激活框动画、庆祝动画必须支持暂停、停止、手动继续与减少动效。
4. 关键组件语义：Mentor FAB、建议/聊天切换、C3 当前步骤、播放/录音状态必须具备完整 name/role/value/state。
5. 手动实测补齐：TalkBack、VoiceOver、外接键盘、系统大字号、深浅色、高对比度、减少动效。

### P1 紧随其后

1. 对比度与非文本对比度审计。
2. 花园拖动和滚动练习流的键盘替代路径。
3. 全量本地化语义标签与错误提示。
4. Growth、Garden、Discover 等次级路径的辅助技术验证。

## 5. 最佳实践建议

1. **一屏只服务一个主任务**：首页服务“现在练”，练习页服务“现在说”，不要把同步、解释、设置和主动作放在同一视觉层。
2. **用用户语言替代系统语言**：把“机制”翻译成“你现在可以做什么”，避免直接暴露实现细节。
3. **以渐进披露管理复杂性**：默认层只给最小可行动信息，细节和高级功能按需展开。
4. **把无障碍当作状态设计问题，不只是标签问题**：动态交互、焦点、动效和恢复路径才是当前最大的可访问性风险。
5. **保持离线优先，但把能力说清楚**：统一表达“先练习，稍后再同步”，让离线能力成为用户信任的一部分。
6. **建立统一术语表**：围绕“场景、活动、短语、成长、同步、建议”收敛正式产品语言，禁止在正式 UI 混入内部状态词。

## 结论

Baby Talk 2 Phase 1 已经具备清晰的产品抓手：它不是教英语知识，而是在育儿真实情境中帮助父母自然开口。这一点非常对。

当前最大的阻力不是缺功能，而是“界面把系统复杂性过多地交给了用户”。如果先完成三件事：
1. 收起工程态，聚焦首页和练习页的单一任务；
2. 明确 4-tab + Drawer + Mentor FAB 的职责边界；
3. 补齐动态交互层的无障碍播报、焦点和动效控制；

这个产品会从“方向正确的原型”更快进入“能长期陪伴父母 daily use 的产品”。
