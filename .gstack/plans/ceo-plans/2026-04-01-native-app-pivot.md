# CEO Plan: Baby Talk 2 - Phase 1 Native App Pivot

## Core Decision

Phase 1 放弃 Flutter Web，直接用 Flutter Native (Android APK + iOS i4Tools 自签名) 开发。微信分享通过简单 HTML landing page（不含 OG 标签）实现。

### Why This Change

1. Flutter Web 在微信内置浏览器中的技术限制太多（MediaRecorder、Web Speech API 被屏蔽、2MB+ bundle size）
2. Phase 1 原计划中多个功能被标记为 "native-only"，导致 Phase 1 产品不完整
3. 10-20 个测试用户可以直接装 APK / i4Tools，不需要零摩擦的 web 分发
4. 改为 native 后，所有功能 Phase 1 直接可用，无需等 Phase 2

### What Changes

| 维度 | 原计划 (Flutter Web first) | 新计划 (Flutter Native first) |
|------|--------------------------|------------------------------|
| 分发 | 微信链接打开 web app | Android APK + iOS i4Tools 自签名 |
| 录音 | Phase 2 native only | Phase 1 直接可用 |
| 语音备忘录 | Phase 2 native only | Phase 1 直接可用 + 服务器存储 |
| 推送 | Web Push (不可靠) → in-app banner | flutter_local_notifications 本地推送 |
| AI 教练语音输入 | Phase 2 native only | Phase 1 直接可用 (阿里云 ASR) |
| 离线 | Service Worker (微信不可靠) | Hive 本地存储 (完全可靠) |
| 微信分享 | 分享 app 链接 | 分享 landing page 链接 |
| OG 分享卡片 | Phase 1 (需要微信平台注册) | Phase 2 |

## Vision

实时双语育儿伴侣，让中国父母在日常场景中自然地对宝宝说英语。不是"学英语"，是"陪宝宝说英语"。Phase 1 验证核心假设：父母会不会真的每天对着宝宝说英文短语并坚持下来？改为 native 让 12 个月理想状态（语音优先的沉浸式教练）更近了，不是更远了。详见 `docs/designs/baby-talk-extended-mvp.md`。

## 技术架构变更

### Frontend
- Flutter (Dart) 编译为 Android APK + iOS IPA
- 不编译 Flutter Web
- ~95% 代码跨平台共享

### 音频架构
- **TTS 播放:** audioplayers 包，预生成音频作为 assets 打包
- **录音:** record 包 (native API, 不是 Web MediaRecorder)
- **语音识别:** 阿里云 ASR SDK (Mandarin)
- **语音备忘录存储:** 本地 + 阿里云 OSS 上传

### 数据架构
- **用户认证:** 手机号+验证码 (阿里云 SMS) + 账号密码登录选择。user_id 为服务器生成的 UUID，绑定到手机号。
- **本地存储:** Hive (NoSQL, 高性能, Flutter native)
- **服务器同步:** 阿里云 FC/ECS API, 基于 user_id 认证
- **语音文件:** 阿里云 OSS
- **离线策略:** 所有种子数据 + TTS 音频打包为 assets。进度数据 Hive 本地存储。有网时后台同步（单向上传备份，last-write-wins）。
- **多设备策略:** Phase 1 为单设备使用。登录系统确保数据与用户绑定。重装 app 后登录可恢复服务器端数据。Phase 2 加跨设备实时同步。

### 版本更新策略
- Phase 1: 新版 APK/IPA 通过微信群发给测试用户，覆盖安装
- 无 OTA 更新机制
- Phase 2: 应用市场更新

### 推送通知
- Phase 1: flutter_local_notifications + alarm_manager (纯本地定时)
- Phase 2: JPush + 厂商通道 (如果用户反馈通知丢失)

## iOS i4Tools 自签名注意事项

- 签名有效期 7 天，到期后 app 无法打开
- 需要定期给测试用户重新发送签名后的 IPA
- 用户需要在 iOS 设置中"信任"开发者证书
- 建议在 landing page 上放 iOS 安装教程
- Phase 2 升级到 TestFlight 后此限制消除

## Known Risks (Updated)

1. **iOS 自签名 7 天限制。** 测试用户每 7 天需要重新安装。对非技术用户不友好。Mitigation: 提供详细安装教程 + 微信群通知提醒重签。Phase 1 iOS 测试为 "best effort"，核心验证依赖 Android 用户。Phase 2 购买 Apple Developer 账号解决。
2. **阿里云 ASR 在噪声环境中的准确率。** 宝宝哭闹时的语音识别质量未知。Mitigation: 始终保留文字输入 fallback。设置 STT 置信度阈值 (<70% 回退到文字输入)。Layer 0 tech spike 验证。
3. **语音备忘录服务器存储需要 PIPL 合规。** 音频数据是个人信息，上传前需要用户同意。Mitigation: Onboarding 流程中集成 PIPL 隐私同意弹窗，首次录音前再次确认。
4. **LLM API 从中国访问。** OpenAI/Anthropic API 可能需要代理。Layer 0 tech spike 做 API 选型决策（通义千问 vs OpenAI + 代理）。
5. **阿里云 ASR Flutter 集成成熟度。** 可能没有现成的 Flutter plugin，需要通过 Platform Channel 桥接原生 SDK。Layer 0 tech spike 验证。
6. **之前的风险仍然适用：** ICP 备案、PIPL 合规、短语内容扩展。
