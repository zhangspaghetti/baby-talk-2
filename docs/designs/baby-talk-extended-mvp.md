## Vision (Long-term North Star, NOT current scope)

The following describes the Phase 3+ ideal. Ambient listening, community features, and Bluetooth earpiece delivery are future phases. The AI phrase request feature (#12) ships in Phase 1 with LLM + RAG + knowledge base + text input. Phase 2 adds voice input via native app.

### 10x Check
A real-time bilingual parenting companion that makes Chinese parents FEEL fluent. Not "here are phrases to repeat" but "I'm with you right now, helping you talk to your child." The app infers context from the parent's description, returns the right English phrase grounded in positive parenting methodology. The knowledge base grows with every parent interaction, making the system smarter and cheaper to operate over time. Plus community: Chinese parents in WeChat groups sharing their baby's first English response, mentoring each other.

### Platonic Ideal
An always-on ambient intelligence that makes the parent FEEL fluent. The parent forgets they're using an app. The growth dashboard isn't stats, it's a visual timeline of their child's language journey, with audio recordings of key moments ("first time she said 'ball' back to you"), generating a keepsake the parent treasures.

The feeling: "I'm giving my daughter a gift no amount of money could buy. And I'm getting better at English too."

## Accepted Feature Specs (New Expansions)

### 9. Phrase of the Day Widget
- **Location:** Top of Smart Home screen, above the "Today's roadmap activities" section. Card-style widget with the English phrase, Chinese translation, and a play-audio button.
- **Selection logic:** Each day at midnight local time (client-side using device clock, no server timezone tracking needed), select one phrase the parent has NOT yet mastered from the current stage's available phrases. `phrase_of_day_date` in local state is compared against the current device date. Prefer phrases from scenes the parent hasn't visited in 3+ days (novelty). If all phrases mastered, pick a random phrase from the most recently active scene.
- **Interaction:** Tapping the widget opens the phrase's scene coaching screen. No separate tracking, the phrase of the day is just a navigation shortcut.
- **Failure states:** No phrases available (all mastered, no stage assigned yet) -> show a motivational message instead ("You've mastered all phrases for this stage! Keep practicing."). Audio playback fails -> show text only.
- **Data:** No new model. Uses existing Phrase and UserProgress models. Adds `phrase_of_day_date: ISO8601` and `phrase_of_day_id: string` to local state (not persisted to server, recomputed daily).

### 10. "You've Been Quiet" Gentle Nudge
- **Trigger:** On app open, if `last_active` timestamp is > 48 hours ago. Checked locally (no server round-trip needed).
- **Display:** In-app banner at the top of the Smart Home screen. Warm tone: "She still needs to hear your voice. Even 'good morning' counts." with the child's name inserted if available. Dismiss button (X). Once dismissed, don't show again until next 48h inactivity period.
- **Frequency cap:** Maximum once per 48h inactivity period. If the parent dismisses and doesn't use phrases, the next nudge appears after another 48h of inactivity (not immediately on next open).
- **Failure states:** `last_active` is null (first-time user) -> don't show nudge. `child_name` not set -> use generic "your little one" instead.
- **Data:** Adds `nudge_dismissed_at: ISO8601 | null` to local state. No server-side data.

### 11. "Say It Together" Couple Mode
- **Activation:** Toggle button on the phrase coaching screen. Same device, both parents looking at the screen together. NOT multi-device (no networking, no login, no pairing).
- **Display:** Phrase card switches to extra-large text (32px+ English, 24px+ Chinese), reduced UI chrome (hide coaching tips, hide reaction buttons during countdown). Full-screen-ish layout optimized for visibility from 1-2 meters away.
- **Flow:** Parent taps "Say Together" -> 3-2-1 countdown (large animated numerals with audio tick) -> phrase appears full-screen -> both parents read it aloud -> tap "Done" to return to normal coaching flow.
- **Why this isn't multi-user complexity:** No second user account, no data model changes, no device pairing. It's purely a display mode toggle on the existing phrase card. The parent who owns the device still taps reactions and tracks progress. The spouse is just reading along.
- **Failure states:** None meaningful. It's a CSS/layout toggle with a countdown timer.
- **Data:** No new model. Adds `couple_mode_enabled: boolean` to local UI state.

### 12. AI Phrase Request
- **Location:** Floating action button (FAB) on every scene coaching screen, labeled "Ask Coach" or similar. On Smart Home, appears as a secondary action button below the Phrase of the Day widget (not a FAB, to avoid two floating buttons).
- **Input (Phase 1, Flutter Web):** Text input only. Parent types a Chinese description of their situation. Voice input deferred to Phase 2 native app (Web Speech API is unreliable in WeChat's in-app browser on iOS, see Known Risks).
- **Input (Phase 2, native):** Voice input via Alibaba Cloud ASR (Mandarin). Text input remains as fallback.
- **Processing:** Phase 1 = LLM API call with RAG knowledge base + parenting methodology system prompt (text input only). Embedding search against knowledge base first, LLM fallback for unknown scenarios. Phase 2 = add voice input via Alibaba Cloud ASR on native.
- **Output:** English phrase + Chinese translation + coaching tip + TTS audio (generated on-the-fly via same TTS pipeline as curated phrases: edge-tts in dev, Alibaba Cloud TTS in prod. No pre-caching; audio generated on-demand per request). Displayed in a modal card matching the existing phrase card design.
- **Latency budget:** < 3 seconds for text display (LLM streaming via SSE endpoint, not raw HTTP streaming. Note: Flutter Web's `dart:html` HttpRequest has streaming limitations, use server-sent events). < 5 seconds for TTS audio generation. Show a loading state with "Thinking..." animation. Verify streaming display works in WeChat's in-app browser during spike.
- **LLM safety:** The system prompt enforces positive parenting methodology. Additionally, a lightweight client-side filter rejects obviously inappropriate input (profanity, non-parenting queries). LLM output is served directly to the user (no human review gate in Phase 1). Phase 2 adds the human review queue + RAG knowledge base for approved phrases.
- **Rate limiting:** Maximum 10 AI requests per user per day. Counter is server-side, resets at midnight UTC (accept that UTC midnight doesn't align with local midnight, fine for Phase 1). Client displays remaining requests. Prevents abuse and controls LLM costs.
- **Failure states:** LLM timeout (>10s) -> "Sorry, I'm having trouble thinking right now. Try again?" with retry button. LLM returns empty/malformed response -> show error with retry. Network offline -> "This feature needs internet. Try one of the pre-loaded phrases instead." Rate limit exceeded -> "You've asked 10 questions today. More tomorrow!"
- **Data:** New model `PhraseRequest { id, user_id, input_text, input_language, generated_phrase_en, generated_phrase_zh, generated_tip, timestamp, was_helpful: boolean | null }`. The `was_helpful` field captures thumbs up/down feedback after the phrase is shown.
- **Admin review (Phase 2):** Founder reviews PhraseRequests via a simple admin page (server-rendered, not in the Flutter app). Approved phrases get added to the knowledge base with embeddings. This is a manual process in Phase 2, automated in Phase 3.

## Known Risks / Open Questions (Extended Plan)

1. **Web Speech API blocked in China.** Google's speech recognition servers (used by Web Speech API) are blocked in mainland China. Voice input for AI phrase requests is NOT feasible on Flutter Web for the primary user demographic. Phase 1 uses text-only input. Phase 2 native app uses Alibaba Cloud ASR.
2. **LLM API access from China.** OpenAI and Anthropic APIs may require proxy routing from China. Consider using a China-accessible LLM (Alibaba Cloud Tongyi Qianwen, Baidu ERNIE, or a self-hosted model) to avoid latency and reliability issues.
3. **Cross-lingual embedding quality for RAG (Phase 2).** Semantic similarity between Chinese scene descriptions and English phrases requires multilingual embeddings. The 0.90 -> 0.85 similarity threshold (see Risk #7) needs empirical tuning with real Chinese parent inputs. Paraphrases like "宝宝不肯穿衣服" and "孩子早上不配合穿衣" describe the same scenario but may score differently.
4. **Chinese scene description authoring.** The RAG knowledge base (Phase 2) needs high-quality Chinese scene descriptions for all 90 seed phrases. This is a content creation task. Owner: founder. Timeline: created alongside Phase 2 RAG implementation.
5. **Prior plan risks still apply:** WeChat sharing complexity, push notifications in China (FCM blocked), audio recording on Flutter Web, PIPL compliance, phrase content expansion from 60 to 90 phrases. See prior CEO plan for details.
6. **LLM cost trajectory.** At 10 requests/user/day, 100 users = 1000 LLM calls/day. At ~$0.01-0.03 per call (Claude Haiku or equivalent), that's $10-30/day. Manageable for Phase 1. RAG in Phase 2 reduces this by 60-80% as the knowledge base grows.
7. **RAG cold-start (Phase 2).** The knowledge base starts with only 90 entries. Similarity search may return poor matches until the knowledge base reaches ~500+ entries from real user interactions. Mitigation: set a higher similarity threshold (0.90) during cold-start, falling to 0.85 after 500 entries.

## AI Phrase Request Architecture

### Parenting Methodology Alignment
All AI-generated phrases AND the 90 curated seed phrases must be grounded in positive parenting methodology from authoritative sources:
- "The Awakened Family" (Shefali Tsabary)
- "Raising Boys" / "Raising Girls" (Steve Biddulph)
- "You Are Your Child's Best Toy" (Kim John Payne)
- "Playful Parenting" (Lawrence Cohen)
- Matsuda's Baby & Child Care Encyclopedia
- AAP Caring for Your Baby and Young Child
- "A Good Mother Is Better Than a Good Teacher"

Principles enforced in LLM system prompt:
- Positive discipline only. No shaming, no punishment-oriented language.
- Emotional validation first. "I see you're upset" before "food goes on the plate."
- Age-appropriate expectations. Don't expect a 12-month-old to "understand rules."
- Parent empathy. The app is a supportive friend, not a judging expert.

### RAG Knowledge Base Architecture (Phase 1 — ships with MVP)

Phase 1 ships with full RAG: LLM + knowledge base + text input. Phase 2 adds voice input on native.

```
Phase 1 (MVP, Flutter Web):
Parent input (text only)
  -> Embedding search against knowledge base (multilingual embeddings)
    |-- Match found (similarity > 0.90 during cold-start, > 0.85 after 500 entries)
    |   -> Return pre-approved phrase (a phrase previously reviewed and added to the KB by the founder)
    |-- No match
        -> LLM call (with parenting methodology system prompt)
        -> Return phrase to parent
        -> Log to "pending review" queue
        -> Founder reviews via admin page -> Approve (add to knowledge base) or discard

Phase 2 (native app):
Same as Phase 1, plus:
  -> Voice input via Alibaba Cloud ASR (Mandarin) with text fallback
```

Knowledge base seeded with:
- 60 curated phrases + their Chinese scene descriptions (authored by founder pre-launch)
- Parenting methodology principles as context chunks
- Phase 2 expands to 90 phrases with additional scene descriptions

Growth trajectory:
- Similar parent situations share pre-approved responses (LLM cost flatlines as user base grows)
- Founder review gate ensures methodology alignment before knowledge base entry
- "Pending review" queue doubles as product research: shows which scenarios parents encounter most

Vector storage:
- Phase 1 launch: in-memory (expected <1000 entries, sufficient for MVP with 10-100 users)
- Migration trigger: when entries exceed 5,000 OR query latency exceeds 200ms
- Migration target: Alibaba Cloud Elasticsearch with vector plugin

## Key Implementation Decisions

- **Tech stack:** Flutter Web first (MVP) -> Android (Phase 2) -> iOS (Phase 2)
- **TTS:** edge-tts for dev/MVP, Alibaba Cloud TTS for production
- **Audio loading:** On-demand from backend, cached locally after first play
- **Phrase count:** Phase 1 ships with 60 seed phrases (10 per scene x 6 scenes). Phase 2 expands to 90 phrases (5 beginner + 5 intermediate + 5 advanced per scene), authored alongside RAG scene descriptions.
- **WeChat sharing:** Phase 1 shares as plain URL. Custom OG card deferred.
- **Pronunciation + voice memo:** Native-only. Hidden on Flutter Web with "download app" prompt.
- **AI phrase generation:** Phase 1 = LLM call + RAG knowledge base (text input only on web). Phase 2 = add voice input on native via Alibaba Cloud ASR.
- **LLM provider:** Consider China-accessible LLM (Alibaba Tongyi Qianwen, Baidu ERNIE) for production. Claude/GPT for development.
- **Vector DB for RAG:** Start with in-memory (<1000 entries). Migrate to Alibaba Cloud Elasticsearch when entries exceed 5,000 or query latency exceeds 200ms.
