## Vision (Long-term North Star, NOT current scope)

The following describes the Phase 3+ ideal. None of this is in the current build scope.
Ambient listening, community features, and Bluetooth earpiece delivery are future phases.

### 10x Check
A real-time bilingual parenting companion. Not "here are phrases to repeat" but "I'm with you right now, helping you talk to your child." The app listens to the ambient scene, infers context, and whispers the next English phrase into the parent's ear via Bluetooth earbuds. The parent never touches the phone. Plus community: Chinese parents in WeChat groups sharing their baby's first English response, mentoring each other. The emotional fuel isn't just the app — it's the tribe.

### Platonic Ideal
An always-on ambient intelligence that makes the parent FEEL fluent. The parent forgets they're using an app. The growth dashboard isn't stats — it's a visual timeline of their child's language journey, with audio recordings of key moments ("first time she said 'ball' back to you"), generating a keepsake the parent treasures.

The feeling: "I'm giving my daughter a gift no amount of money could buy. And I'm getting better at English too."

## Accepted Feature Specs

### 1. "First Word" Celebration Screen
- **Trigger:** Parent logs reaction = "babbled" for the first time ever (first occurrence only)
- **Happy path:** Full-screen animation + generated card with child's name, phrase, date. Share button opens device share sheet with a plain URL link.
- **Accidental tap:** If parent tapped "babbled" by mistake, the celebration screen has a "Not quite yet? Dismiss" option. The `first_babble_celebrated` flag resets.
- **Failure states:** Share fails (offline) -> save card locally, retry later. No babbled event yet -> feature hidden.
- **Data:** New field `first_babble_celebrated: boolean` on UserProgress. Card image generated client-side (Flutter canvas).
- **WeChat sharing:** Phase 1 shares as plain URL (no custom OG card). User taps share -> copies link or opens share sheet. Custom OG card preview with server-rendered meta tags is deferred to TODOS.md.

### 2. Pronunciation Comparison (NATIVE APP ONLY — hidden on Flutter Web)
- **Phase 1 availability:** Hidden on Flutter Web. Shows "download the app for pronunciation practice" message. Ships functional on Android/iOS in Phase 2.
- **What it does:** Parent taps "record", says the phrase, taps "stop". App plays back their recording next to the TTS reference. No scoring, no waveform, no grading. Just two audio tracks the parent can A/B.
- **Inputs:** Microphone audio (WAV/WebM depending on platform)
- **Storage:** Recordings stored locally only (device). Not uploaded. Privacy-safe.
- **Failure states:** Microphone permission denied -> show explanation + settings link. Recording too short (<1s) -> prompt retry. Flutter Web on iOS Safari in WeChat -> may not support MediaRecorder API. Fallback: hide the record button, show "download the app for pronunciation practice."
- **Data:** No new model. Recordings are ephemeral (overwritten each time).

### 3. Daily Phrase Push Notification
- **What:** One phrase with scene context, delivered at 6pm local time. Example: "Tonight at bath time, try: 'Splash splash! Can you splash with me?'"
- **"Contextual" means:** Based on child's current stage (filter stage-appropriate scenes) + scene rotation (cycle through unlocked scenes, don't repeat same scene two days in a row) + within selected scene, pick the highest-order unmastered phrase (mastered = configurable threshold, default 3+ "I said it" taps). If all phrases mastered in all scenes, pick a random phrase from the most recently active scene.
- **Platform:** Flutter Web -> Web Push API (requires Service Worker + user permission grant). NOTE: FCM and JPush native SDK both require native apps. **Phase 1 web-only fallback:** In-app banner shown on first app open after 6pm if no push permission or native SDK unavailable. Push notifications only fully functional on Android/iOS (Phase 2).
- **Notification permission prompt:** Shown on first session completion ("Want daily English tips? Allow notifications."). Not on first launch (too early, parent hasn't experienced value yet).
- **Failure states:** Notification permission denied -> show in-app banner instead at app open. User in Do Not Disturb -> notification queued by OS.

### 4. Weekly Voice Memo Diary (NATIVE APP ONLY — hidden on Flutter Web)
- **Phase 1 availability:** Hidden on Flutter Web (same MediaRecorder limitation as pronunciation). Shows "download the app for voice diary" message. Ships functional on Android/iOS in Phase 2.
- **What:** Once per week (Sunday evening), prompt parent to record a 30-second voice memo about their baby's English journey. Parent records themselves speaking (not the baby).
- **Prompt delivery:** In-app banner on first app open after Sunday 6pm. If native app with push: push notification.
- **Storage:** Recordings saved to device local storage. Cloud backup is a Phase 2 feature (requires Alibaba Cloud OSS + PIPL consent flow for audio data).
- **Inputs:** Microphone audio, max 30 seconds, auto-stop at limit.
- **Failure states:** Same microphone permission flow as pronunciation comparison. Storage full -> warn and offer to delete oldest memo.
- **Data:** New model `VoiceMemo { id, timestamp, duration_seconds, local_path }`. No `user_id` needed for Phase 1 (local-only, single device). Displayed chronologically in a "Journey" tab (new tab in bottom navigation).

### 5. Phrase Difficulty Progression
- **Levels:** beginner / intermediate / advanced. Curated by content author (metadata on each phrase, not auto-assigned).
- **Data:** New field `difficulty: "beginner" | "intermediate" | "advanced"` on Phrase model.
- **Advancement:** Driven by the Roadmap stage system (see Feature 6). Stage determines which difficulty tiers are AVAILABLE. Mastery threshold (configurable, default 3+ taps) determines progress WITHIN a tier. Example: Stage 2 (6-12mo) makes only beginner phrases available. Stage 4 (18-24mo) unlocks intermediate. Mastery within a tier is used for progress tracking and phrase recommendations, NOT for unlocking the next tier.
- **UI:** Difficulty badge on each phrase card. Progress bar per difficulty level on the scene screen.
- **Phrase count:** Expand from 10 to 15 phrases per scene (5 beginner, 5 intermediate, 5 advanced) = 90 total phrases.

### 6. Expert English Immersion Roadmap
- **What:** Age-based immersion methodology roadmap with 5 developmental stages (0-36 months). Guides parents through the complete English immersion journey, not just phrase cards. Based on established research (Krashen's input hypothesis, TPR, OPOL method).
- **Content source:** Research-backed expert content. Published methodologies adapted into practical Chinese-language parent guidance.

**Stage System:**

| Stage | Age | Focus | Key Methodology | Scenes Unlocked | Activity Types |
|-------|-----|-------|-----------------|-----------------|----------------|
| 1. Exposure | 0-6 mo | Pure input | Parentese, songs, ambient | Diaper, Feeding, Bedtime | Phrase cards, nursery rhyme guides |
| 2. Routine Talk | 6-12 mo | Routines + TPR | TPR commands, daily narration | + Bath, Dressing, Play | + TPR exercises |
| 3. First Words | 12-18 mo | Naming + pointing | Object naming, simple TPR, picture books | + Reading Time, Walk | + Picture book guides |
| 4. Sentences | 18-24 mo | Two-word combos | Expansion, guided cartoons | + Cartoon Time, Shopping | + Cartoon watching guides |
| 5. Conversation | 24-36 mo | Questions + stories | WH-questions, storytelling, role play | + Story Time, Pretend Play | + Conversation starters |

**Activity Types (expand beyond phrase cards):**
1. Phrase Cards (existing) — "Say this during this scene"
2. TPR Exercises — "Say 'arms up!' while lifting baby's arms" with gesture descriptions
3. Picture Book Guides — "This week, read 'Brown Bear.' Here's the parent script per page."
4. Cartoon Watching Guides — "Watch this 3-min Peppa clip together. Before/during/after scripts for parent."
5. Methodology Tips — "Why TPR works: connecting words to actions is 10x more effective than words alone."

**Integration with existing features:**
- Smart Home screen shows "Today's roadmap activities" — mix of phrase cards, TPR exercises, book/cartoon sessions based on stage
- Scene recommendations driven by stage (not just time-of-day). Earlier stages' scenes remain available (additive, not replacing).
- Phrase difficulty driven by stage (Stage 2 = beginner only, Stage 4 = intermediate unlocks). See Feature 5 for details.
- Progress dashboard shows roadmap progress: "Stage 3: First Words. 60% complete."

**Stage advancement:** Automatic, based on child_age_months. When parent enters child's birthdate during onboarding, the app calculates age and assigns the appropriate stage. As the child ages, the stage advances automatically. Parent can also manually override the stage (in case the child is developmentally advanced or needs more time at a stage). Stage advancement is one-way unless manually overridden.

**Stage progress calculation:** `stage_progress_pct` = (unique activities completed in current stage) / (total activities in current stage) * 100. `activities_completed` map stores completion count per activity (integer, incremented each time the activity is done — allows tracking repeat engagement for daily activities).

**Content pipeline:** Phase 1 content authored by founder using LLM as drafting tool, validated against published research (Krashen, TPR, OPOL). Stored as static JSON seed data in the Flutter app (same pattern as phrase seed data). No CMS needed for Phase 1. Picture book and cartoon references are recommendations (not embedded content) — no IP/licensing issues.

**Data model:**
```
Stage {
  id: string
  name: string
  age_min_months: number
  age_max_months: number
  focus: string
  methodology_zh: string       // Chinese explanation for parent

Activity {
  id: string
  stage_id: string
  type: "phrase_card" | "tpr_exercise" | "picture_book_guide" | "cartoon_guide" | "methodology_tip"
  title_zh: string
  content_zh: string           // Chinese instructions for parent
  english_content: string      // English phrases/scripts
  audio_urls: [string]

UserRoadmap {
  current_stage_id: string
  child_birthdate: ISO8601           // Used to auto-advance stage
  child_age_months: number           // Computed from birthdate
  stage_override: string | null      // Manual override, null = auto
```

## Known Risks / Open Questions

1. **WeChat sharing from Flutter Web.** WeChat's JS-SDK for custom share cards requires a registered WeChat Open Platform app ID and domain verification. The share page needs server-side rendering for OG tags. This is a real integration task, not a trivial share button. Spike needed.
2. **Push notifications in China.** FCM is blocked. JPush or Alibaba Cloud MPS required. This adds a backend dependency and a native SDK integration for Android. Flutter Web push may not work reliably in WeChat's in-app browser.
3. **Audio recording on Flutter Web.** The `record` package has inconsistent support on web, especially iOS Safari within WeChat's in-app browser. Pronunciation comparison and voice memo features may need to be Android/iOS-only, with a "download the app" prompt on web.
4. **PIPL compliance is more than a TTS swap.** Full compliance requires: data residency (Alibaba Cloud), user consent flow, Privacy Policy registered with a Chinese entity, and potentially ICP filing. This is a separate workstream, not a line item in TTS migration.
5. **Phrase count expansion.** Moving from 60 to 90 phrases (to support 3 difficulty levels) requires additional content curation and TTS generation.

## Key Implementation Decisions
- **Tech stack:** Flutter Web first (MVP, share via WeChat links) -> Android (Phase 2, voice features) -> iOS (Phase 2, after Android). "First" means web-only MVP ships first. Native apps are post-validation.
- **TTS strategy:** edge-tts (free, Azure Neural Voices) for development/MVP. Migrate to Alibaba Cloud TTS for production (PIPL compliance, SLA).
- **Audio loading:** On-demand from backend (Alibaba Cloud OSS). NOT bundled in frontend. Cached locally after first play.
- **Mastery threshold:** Configurable server-side constant (default 3). Not hardcoded. Can be tuned without migration.
- **Mini Program references in design doc are superseded.** Flutter Web shared via WeChat links is the confirmed approach.
- **WeChat sharing:** Phase 1 shares as plain URL (user opens in browser). Custom OG card preview deferred to TODOS.md.
- **PIPL compliance:** Gated on production launch. Consent flow + privacy policy built in Phase 1. ICP filing started in parallel.
- **Social awkwardness validation:** Built into Phase 1 as post-session comfort survey.
- **Pronunciation comparison + voice memo:** Marked as native-app-only. Hidden on Flutter Web with "download app" prompt.
- **Approach:** B (Flutter Web) — best long-term architecture for voice features, ~95% code sharing
