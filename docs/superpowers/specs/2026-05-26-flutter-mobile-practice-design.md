# Flutter Mobile Practice 页面交互结论

日期：2026-05-26  
状态：Practice 子设计已确认（待合入整体 QA 迭代设计）

## 1. 背景与目标

本轮 QA 发现 Practice 页面存在三个核心问题：

1. 提示和说明占据过多空间，练习卡片没有始终处在首屏最显眼位置。
2. 发音播放体验不可信，不能使用杂音或空路径，需要连接后端发音服务。
3. 下一句内容需要连接后端生成能力，但界面不应暴露技术词。

本次确认的方向是：Practice 是“当前一句的完成界面”，不是小课程，也不是 onboarding 的聊天延续。英文句卡必须始终是首屏视觉中心，家长可以直接说，听发音只是辅助。

非目标：

- 不把 Practice 做成长篇教学页。
- 不要求用户先听再说。
- 不展示拼音或英文转写。
- 不让宝宝反应成为完成一句的门槛。
- 不向用户暴露 TTS、LLM、接口、模型等技术词。

## 2. 已确认方案

采用“句卡优先 + 单手完成 + 轻量反馈”。

核心原则：

1. 英文句子是第一视觉重点。
2. 中文只作为小号释义，帮助家长确认意思。
3. 小禾老师在 Practice 中比 Onboarding 更弱，只保留一行短提示。
4. Coach tip 默认收起为小入口，用户主动需要时才展开。
5. 底部主按钮固定，服务单手操作。
6. 用户可以直接对宝宝说，点击 `说完了` 即保存本句。
7. 宝宝反应为可选记录，选择后自动进入下一句。

## 3. 默认练习态

页面结构：

1. 顶部标题：`今日一句`
2. 顶部副标题：当前场景，如 `喂饭 / 一句就够`
3. 小禾轻提示：`小禾：会说就直接说。`
4. 中央句卡：
   - 场景标签
   - 当前句序
   - 英文主句
   - 中文释义
   - `听小禾读` 辅助按钮
5. Coach tip 小入口：`提示`
6. 底部主按钮：`说完了`
7. 底部次级按钮：`换一句`、`结束`

设计要求：

- 句卡位于首屏中心，面积和字号明显高于其他元素。
- Coach tip 不得推开句卡或让句卡掉到首屏下方。
- 小禾提示不得变成长聊天。
- 触控目标不小于 44px。

## 4. 发音播放状态

发音播放连接后端发音服务，但 UI 只使用用户语言。

状态文案：

- 未播放：`听小禾读`
- 准备中：`小禾准备读`
- 播放中：`播放中`
- 播放完成：`再听一次`
- 失败：`这句没读出来，点我重试`

设计要求：

- `听小禾读` 是辅助动作，不是主路径。
- 用户不需要等待发音播放才能点击 `说完了`。
- `听不到？` 不在正常路径提前出现；声音失败入口只在真实失败后出现。
- 失败重试不得使用技术错误码。

## 5. 说完后与宝宝反应

点击 `说完了` 后：

1. 本句立即保存。
2. 页面展示 `已保存本句`。
3. 展示宝宝反应按钮。
4. 不选择反应时，用户可点击 `跳过，下一句`。

宝宝反应必须按场景变化，不使用一套固定词覆盖所有场景。Onboarding 使用固定 3 个选项（有回应/安静了/没反应）以降低首次用户决策成本，Practice 使用场景特定选项（如喂饭：有回应/吃了一口/没反应）。这是有意的设计差异，详见组件规格。

示例：

- 喂饭：`有回应`、`吃了一口`、`没反应`
- 喝水：`有回应`、`喝了一口`、`没反应`
- 换尿布：`有回应`、`配合了`、`没反应`
- 洗澡：`有回应`、`配合了`、`没反应`
- 睡前：`有回应`、`安静了`、`没反应`
- 出门：`有回应`、`配合了`、`没反应`

选择反应后的规则：

1. 反应按钮进入选中态。
2. 显示与场景和反应匹配的反馈文案。
3. 约 1.35 秒后自动进入下一句。（V21 Onboarding 延长至 2.5-3 秒并增加可见倒计时进度条。Practice 保留 1.35 秒用于会话内连续使用；Onboarding 对首次用户使用更长时间，降低分心场景下的操作成本。）
4. 若用户在自动跳转前点击 `换一句`、`结束` 或返回，必须取消自动跳转。

反馈文案示例：

- `记下来了，小禾给你下一句。`
- `记下来了，喂饭时可以再用。`
- `记下来了，这句适合睡前留着用。`
- `没关系，换一句试试。`

## 6. 下一句状态

下一句内容连接后端生成能力，但 UI 不暴露技术词。

状态文案：

- 准备中：`下一句准备中`
- 说明：`保持在这个页面就好，小禾正在给你换一句适合现在场景的话。`
- 失败：`换一句没准备好，点我重试`
- 失败说明：`上一句还在这里。你可以重试，也可以先结束练习。`

设计要求：

- 反应选择后自动下一句时，底部主按钮不可呈现为可点击但无反应的状态。
- 准备失败时必须提供重试和回到本句/结束路径。
- 失败文案不得出现接口、模型、后端、LLM 等技术词。

## 7. Coach Tip

Coach tip 保留，但作为主动求助入口，而不是默认内容。

规则：

1. 默认只显示一个小入口：`提示`。
2. 展开为浮层或 sheet，不推开句卡。
3. 内容最多 1-2 条。
4. 不使用长段落讲解。
5. 不遮挡底部主按钮。

建议提示：

- `先看英文，对宝宝说一次就好。中文只帮你确认意思。`
- `不一定要先听；听小禾读只是辅助你确认发音。`

## 8. 结束态

结束页目标是鼓励真实完成，而不是打分。

页面结构：

1. 顶部：`今天完成了`
2. 小禾提示：`今天这样就很好。`
3. 主标题：`今天已经很好`
4. 总结：`你说出了 N 句。下次打开，小禾会继续给你一句。`
5. 主按钮：`再来一句`
6. 次按钮：`回到场景`

## 9. 可访问性与移动端要求

1. 所有按钮触控目标不小于 44px。
2. 句卡、播放按钮、反应按钮、提示入口需要有清晰语义。
3. 选中反应不能只依赖颜色表达，需要有语义状态。
4. 支持 TalkBack/VoiceOver 测试。
5. 支持 `prefers-reduced-motion`。
6. 小屏下不得出现横向滚动，底部主按钮不得遮挡句卡主要内容。

## 10. 已确认视觉原型

最终确认原型：

- `qa-mobile-practice-v21-card-first.html`

关键调整：

- 移除背景装饰光斑，保持 Warm Paper Kindness 的安静底色。
- 小禾从顶部身份位降为一句轻提示，区分 Onboarding 与 Practice。
- 句卡始终是首屏最显眼元素。
- `听小禾读` 仅为辅助动作。
- 声音失败入口只在真实失败后出现。
- 宝宝反应按场景变化。
- 选反应后自动进入下一句，不选反应才需要手动跳过。

## 11. 后续实现提示

后续进入实现计划时，需要重点关注：

1. Practice 页面应复用 onboarding 第一张句卡的交互模型，但独立于 onboarding 的聊天/引导结构。
2. 发音播放需要通过后端发音服务或统一音频服务获取，不得继续使用杂音或空路径。
3. 下一句需要调用后端生成接口，并将准备中、失败、重试映射为用户语言。
4. 宝宝反应保存应驱动 garden 成长痕迹。
5. 动画和自动跳转需要可取消，避免用户正在结束或换句时被拉回下一句。

本文件仅记录已确认的 Practice 子设计，不代表实现计划已经批准。
