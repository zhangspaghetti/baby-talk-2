# Flutter Mobile Onboarding 交互结论

日期：2026-05-26  
状态：Onboarding 子设计已确认（待合入整体 QA 迭代设计）

## 1. 背景与目标

本轮 QA 发现原 onboarding 存在两个方向上的张力：

1. 原体验有“小禾老师对话式”的陪伴感，但容易变成多轮聊天和较重的信息录入。
2. 真实使用场景常发生在喂饭、换尿布、睡前安抚等家长单手、分心、很难腾出手的时刻。

本次确认的方向是：保留“小禾老师”的陪伴人格，但将 onboarding 和第一句练习压缩为照护场景里的轻提示器，让家长尽快说出一句英文。

非目标：

- 不恢复长聊天式 onboarding。
- 不把第一句练习做成小课程或多步骤打卡。
- 不在 onboarding 中展示拼音或英文转写。
- 不在年龄选择后推断宝宝偏好、性格或能力。

## 2. 已确认方案

采用“小禾老师一句式引导 + 单手快速路径”。

核心原则：

1. 小禾老师保留头像、名字和一句短气泡，承担陪伴和降压作用。
2. 每个关键节点最多出现一句小禾提示，不进入连续聊天流。
3. 主界面只展示当前必要操作，避免解释产品理念。
4. 英文句子是第一视觉重点；中文只作为小号释义。
5. 家长可以不先听发音，看到英文后直接对宝宝说。
6. 完成一句的定义是：家长把这句说出口一次。
7. 宝宝反应是可选记录，不是完成门槛。

## 3. Onboarding 首屏

首屏目标：让用户选择正在发生的照护场景，并尽快开始一句。

页面结构：

1. 顶部显示“小禾老师 / 一句就好”。
2. 小禾老师一句气泡：`选现在的场景就好。`
3. 主标题：`今天先说一句`
4. 一行提示：`选个正在发生的场景`
5. 场景按钮：
   - 喂饭
   - 喝水
   - 换尿布
   - 洗澡
   - 睡前
   - 出门
6. 年龄作为后置入口：`宝宝多大？可稍后补`
7. 底部主按钮：`开始一句`
8. 顶部次要动作：`直接给一句`

设计要求：

- 场景选择是首屏主任务。
- 年龄不和场景同等权重展示，避免首屏判断成本过高。
- 年龄可跳过；如后续实现让年龄影响推荐，必须真实影响句子难度，否则不得暗示个性化推荐。
- `直接给一句` 默认使用当前选中场景，不硬跳到某个未解释场景。

## 4. 第一句练习

主路径：

1. 用户进入场景句卡。
2. 英文句子以最大视觉权重展示。
3. 中文释义作为小号辅助信息展示。
4. 用户可以直接对宝宝说。
5. 用户点击底部主按钮：`说完了`。

辅助动作：

- `听小禾读` 放在句卡内，是辅助按钮，不是主路径。
- 播放完成后按钮变为 `再听一次`。
- `换一句` 是次级动作。
- `结束` 是次级动作。

设计要求：

- 不要求先播放再完成。
- 不展示拼音或英文转写。
- 不让发音提示、教练说明或状态文案挤掉英文句卡。
- 触控目标不小于 44px。

## 5. 宝宝反应记录

点击 `说完了` 后：

1. 本句立即保存。
2. 页面显示 `已保存本句`。
3. 展示轻量宝宝反应区。

反应项确认缩减为三项：

- 有回应
- 安静了
- 没反应

交互规则：

1. 用户选择反应后，按钮进入选中态。
2. 根据反应类型显示短反馈。
3. 等待约 1.35 秒后自动进入下一句。
4. 如果用户不选反应，则需要点击 `跳过，下一句`。
5. 如果用户在自动跳转前点击 `换一句`、`结束` 或返回，必须取消自动跳转，避免竞态。

反馈文案：

- 有回应：`记下来了，小禾给你下一句。`
- 安静了：`记下来了，这句可以留着用。`
- 没反应：`没关系，换一句试试。`

## 6. 结束态

结束页目标是降低被考核感，而不是展示课程成绩。

页面结构：

1. 小禾老师一句气泡：`今天这样就很好。`
2. 主标题：`今天已经很好`
3. 简短总结：`你说出了 N 句。下次打开，小禾会继续给你一句。`
4. 主按钮：`再来一句`
5. 次按钮：`回到场景`

设计要求：

- 不展示排行榜、闯关、分数。
- 不强化宝宝表现评判。
- 鼓励家长完成真实亲子场景中的一句。

## 7. 可访问性与移动端要求

1. 所有主要按钮和反应按钮触控目标不小于 44px。
2. 小禾老师头像为装饰元素时应对屏幕阅读器隐藏；提示气泡需要有语义标签。
3. 交互元素需要有明显 focus 状态。
4. 支持 `prefers-reduced-motion`，自动下一句和播放状态在减弱动效模式下不得造成阅读困难。
5. 页面不得出现横向滚动。
6. 文本字号在移动端保持可读，英文句子可以大，但不能溢出容器。

## 8. 已确认视觉原型

最终确认原型：

演进过程：

- V17 确认英文优先和反应自动下一句方向。

## 9. 后续实现提示

后续进入实现计划时，需要特别关注：

1. Onboarding 与 practice 的边界：第一句可以作为 onboarding 结束后的第一张 practice 卡，但逻辑上应复用练习页能力。
2. 练习句来源应连接后端 LLM 生成接口，不能长期依赖静态本地句库。
3. 发音播放应连接后端 TTS 或统一音频服务，不能使用杂音或空路径。
4. 年龄字段若参与推荐，必须在请求参数和推荐结果中形成真实差异。
5. 宝宝反应保存后应驱动 garden 成长痕迹，但反应记录不得阻塞下一句。
