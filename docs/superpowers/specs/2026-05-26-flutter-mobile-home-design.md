# Flutter Mobile Home 首页交互结论

日期：2026-05-26  
状态：Home V23 子设计已确认（待合入整体 QA 迭代设计）

## 1. 读者与读完后动作

本文件写给产品、设计和 Flutter 实现工程师。

读完后，读者应该能够：

1. 判断 Home 页和 Practice 页的职责边界。
2. 按 Home V23 的信息架构实现 Flutter 首页。
3. 为加载、离线、发音失败、小禾失败、未登录、同步失败和练习完成等状态设计用户可见反馈。
4. 验收首页是否符合 `DESIGN.md` 的 Warm Paper Kindness 方向。

本文件不是实现计划，也不直接批准生产代码改动。进入实现前仍需要拆分任务、确认数据契约和测试范围。

## 2. 背景与目标

此前 Home 方案和 Practice 页面重复度过高，容易让用户感觉“打开首页就是另一个练习页”。这会削弱首页的产品价值，也会让后续花园、发现、成长等模块没有清晰入口。

Home V23 的定位是“今日亲子英语编排入口”：家长打开 app 后，先知道今天适合说哪一句、可以顺手做哪个轻活动、练完后会留下什么痕迹，并且在需要时可以问小禾。

目标：

1. 首页第一视觉锚点是“今日短语”，不是仪表盘或卡片墙。
2. Home 负责今日安排、轻活动、花园痕迹和小禾问答。
3. Practice 只负责“当前一句”的执行，不复制完整首页模块。
4. 未登录、离线、发音失败和小禾失败都不能阻断主路径。
5. 首页必须符合 Warm Paper Kindness：温暖、克制、亲切，不像儿童课程页。

非目标：

- 不把 Home 做成课程列表或任务打卡中心。
- 不把花园做成首页主任务。
- 不在用户界面暴露 TTS、LLM、接口、模型等技术词。
- 不在 Home 中承载完整登录、注册、设置或成长分析。
- 不用 emoji、花哨动效或装饰性渐变制造亲子感。

## 3. 页面职责边界

Home 是今日编排页，Practice 是当前执行页。

Home 承载：

1. 问候和今日场景路线。
2. 今日短语主画面。
3. 今日活动轻入口。
4. 花园痕迹轻摘要。
5. 小禾临时场景建议。
6. 账号与同步入口。
7. 设置、提醒、档案等非主导航入口。

Practice 承载：

1. 当前一句。
2. 中文释义。
3. 读一下。
4. 说完了。
5. 回首页或结束。
6. 低干扰小禾入口。

关键边界：Home 解释“今天怎么开始”，Practice 帮用户“把这一句说完”。

## 4. 信息架构

首页首屏优先级：

1. 今日短语：英文句子、中文释义、读一下、今天先说一句。
2. 今日入口状态：照护者问候、宝宝或场景路线。
3. 可选小活动：三张轻卡片，用户想做时再展开说明。
4. 花园痕迹：练完一句后显示今天留下的痕迹。
5. 小禾：通过首页内联 `问小禾` 轻按钮可见可达，不悬浮遮挡内容，也不替代主路径。
6. 换场景：当前推荐不贴眼前场景时，提供低压力入口打开小禾临时建议。

结构：

```text
顶部栏
  菜单 / BabyTalk + 每天一句亲子英语 / 账号

今日入口
  早上好，林林妈妈
  照护场景 / 喂饭开始
  先说一句，再顺手做一个小活动
  不是现在？换个眼前场景 / 问小禾

今日短语
  One more bite.
  再吃一口 · 适合递勺前后轻轻说一次
  读一下 / 今天先说一句

今日活动
  TPR 小动作
  绘本补一句
  小禾提醒

花园
  今日痕迹 / 小芽
  查看摘要

全局
  首页用内联问小禾和换场景入口打开小禾；Practice 保留低干扰小禾浮动入口
  底部四 Tab：首页 / 发现 / 花园 / 成长
  左上角 Drawer：提醒、宝宝档案、照护者偏好、播放偏好、帮助与反馈
```

## 5. 默认首页态

默认态文案：

- 顶部标题：`BabyTalk`
- 顶部副标题：`每天一句亲子英语`
- 问候：`早上好，林林妈妈`
- 今日路线：`照护场景 / 喂饭开始`
- 入口说明：`先说一句，再顺手做一个小活动。`
- 换场景入口：`不是现在？换个眼前场景`
- 今日短语 CTA：`今天先说一句`
- 播放按钮：`读一下`
- 播放辅助状态：`听一遍，也可以直接开始。`

设计要求：

1. 问候区保持扁平，不做大卡片，不抢短语视觉重心。
2. 英文短语必须是首屏最大、最清晰的文字。
3. 读一下是辅助动作，不是完成一句的前置条件。
4. 今日短语的主 CTA 必须比活动入口更突出。
5. 当前场景不对时，用户可以用轻入口换成眼前场景，不需要先理解发现页或完整场景库。
6. 页面文案使用家长能直接理解的短句，不写设计说明式文案。

## 6. 今日短语

今日短语是首页第一视觉锚点。

内容：

1. 场景标签，如 `喂饭`。
2. 推荐标签，如 `适合现在`。
3. 英文短语。
4. 中文释义和一句极短使用提示。
5. 读一下。
6. 今天先说一句。

交互：

1. 点击 `读一下` 播放当前短语发音。
2. 播放中按钮显示 `播放中`。
3. 播放完成后按钮显示 `再读一次`。
4. 点击 `今天先说一句` 进入过渡页，再进入 Practice。
5. 用户不需要等待播放结束才能进入 Practice。

状态文案：

- 未播放：`听一遍，也可以直接开始。`
- 播放中：`听完就可以说。`
- 播放完成：`可以开始练。`
- 播放失败：`这句没读出来，点我重试。`

## 7. 今日活动

今日活动是 Home 的轻补充，不替代今日短语。

固定三槽位：

1. `TPR 小动作`
2. `绘本一页`
3. `小禾提醒`

展示规则：

1. 首页只显示轻卡片，不展开长说明。
2. 点击活动卡片打开底部做法面板。
3. 面板只说明今天怎么做，不进入复杂任务流程。
4. 活动完成不是首页主 CTA，也不影响今日短语完成。
5. 默认活动粒度控制在 30 秒到 2 分钟；绘本活动是“翻到一页，说一句就停”，不是完整阅读任务。

底部面板按钮：

- `稍后`
- `知道了`

设计要求：

1. 三张活动卡片必须低于今日短语的视觉权重。
2. 活动卡片可以下滑出现，不能压缩首屏短语和主按钮。
3. 活动说明控制在一小段内，避免变成课程讲解。

## 8. 小禾导师

小禾是全局导师，不是首页专属聊天入口。

Home 中：

1. 首页使用内联 `问小禾` 按钮和 `不是现在？换个眼前场景` 打开小禾，不额外悬浮遮挡内容。
2. 打开底部弹层。
3. 用户可以选择常见场景，也可以输入眼前情况。
4. 小禾给一句临时沟通建议。
5. 临时建议可以进入一次练习。
6. 临时建议不替换今日短语，也不改今日路线。
7. 临时建议完成后按真实临时场景留痕；花园摘要不得硬记到今日推荐场景。
8. 用户手写眼前场景时，需要保留该场景标签或归一后的场景名，不能统一落成“临时场景”。

Practice 中：

1. 保留低干扰小禾入口。
2. 入口不能遮挡 `读一下` 或 `说完了`。
3. 小禾只提供临时帮助，不打断当前一句。
4. 从小禾临时建议进入 Practice 时，Practice 需要保留临时来源和场景标签，完成后用于 toast 和花园归因。

设计要求：

1. 小禾入口可见但不喧宾夺主。
2. 小禾弹层不使用长聊天流。
3. 关闭后用户应回到原来的 Home 或 Practice 上下文。
4. 小禾失败时必须保留本地建议或安全兜底文案。
5. 小禾回答后继续提醒“不改今天安排”，避免家长以为今日推荐被替换。

## 9. 账号、菜单与导航

账号与同步：

1. 账号入口固定在右上角。
2. 未登录不阻断首页主路径。
3. 点击账号入口打开轻登录弹层。
4. 文案强调“登录后同步今天说过的句子和花园痕迹”。

左上角菜单：

只承载非主导航入口：

1. 提醒设置。
2. 宝宝档案。
3. 照护者偏好。
4. 播放偏好。
5. 帮助与反馈。

底部导航：

1. 首页。
2. 发现。
3. 花园。
4. 成长。

设计要求：

1. 首页不再把账号、菜单和导航混在同一个入口里。
2. Drawer 不承载 Home、发现、花园、成长等主 Tab。
3. 账号状态只做轻提示，不把用户推去登录才能继续。

## 10. 练习完成与花园痕迹

完成一句后的闭环：

1. 用户在 Practice 点击 `说完了`。
2. 回到 Home。
3. 展示 1.5-3 秒轻 toast，文案按实际完成场景生成。
4. 花园摘要展开。
5. 花园摘要说明今天留下的真实练习痕迹。

toast 规则：

- 今日推荐练习完成：`刚刚这句已经留在喂饭小芽里。`
- 小禾临时练习完成：`刚刚这句已经留在出门痕迹里。`

花园默认态：

- 标题：`花园`
- 入口：`今日痕迹 / 小芽`
- 未完成：`说完一句后，这里会出现一条小芽。`
- 完成后：`今天的小芽来自刚刚说过的一句。`

摘要文案：

- 未完成：`还没有新的痕迹。说完今日短语后，这里会记下一次真实练习。`
- 今日推荐已完成：`喂饭时说过 “One more bite.”。这只是成长痕迹，不需要额外打卡。`
- 小禾临时练习已完成：`出门时说过 “Shoes on.”。这是一次临时场景练习，今日推荐还在这里。`

设计要求：

1. 花园在 Home 中只是痕迹入口，不做复杂成长地图。
2. 完成反馈要轻，不做强庆祝或大动画。
3. 反馈建立“说了一句 → 留下痕迹”的因果。
4. 归因必须基于实际练习来源，不能把小禾临时练习写成今日推荐场景。

## 11. 状态矩阵

| 状态 | 用户看到 |
| --- | --- |
| 加载中 | 保留顶部与底部导航，短语区显示暖纸骨架，不显示空白卡。 |
| 无今日计划 | 给一条安全默认短语和换场景能力，不让首页空掉。 |
| 仅短语可用 | 保留“今天先说一句”，活动区显示“稍后再补充”。 |
| 离线 | 标明“离线也能先练”，小禾改成本地建议。 |
| 音频失败 | 播放按钮显示“再试一次”，短语和进入练习不受阻断。 |
| 小禾失败 | 说明“先给一条本地建议”，保留临时练习入口。 |
| 未登录 | 账号入口轻提示，主路径可继续体验。 |
| 同步失败 | 账号入口显示温和状态，花园保留本地痕迹。 |
| 练习完成 | 轻 toast 说明痕迹已留下，再展开花园摘要；摘要按实际完成的句子和场景展示。 |

## 12. 视觉系统要求

Home V23 必须对齐 `DESIGN.md`。

字体：

1. 英文短语使用 Fraunces。
2. 中文 UI 使用 PingFang SC、Noto Sans SC、Microsoft YaHei 或等价 Flutter 字体栈。
3. 英文 UI 使用 DM Sans。
4. 不使用系统默认字体作为主要设计表达。

颜色：

1. 主背景：`#FFF8F0`。
2. 主 CTA：`#FF8C42`。
3. 英文短语高亮：`#3B8577`。
4. 英文柔和背景：`#D4E8E3`。
5. 文本使用 Warm Paper Kindness 的暖灰层级。

视觉要求：

1. 不使用紫色、蓝紫渐变或儿童教育类高饱和配色。
2. 不使用 emoji 作为设计元素。
3. 不使用大面积装饰光斑、渐变球或无意义图标墙。
4. 卡片只在承载真实交互时使用。
5. 阴影应克制，移除阴影后页面仍应有清晰层级。
6. 中文模块标题和按钮避免过重字重；Flutter 实现中标题和按钮以 700 为上限，pill 以 600-700 为主。
7. 今日短语卡使用 `--shadow-md` 级别的轻阴影，避免做成模板式大浮层。
8. 主 CTA 保留暖橙，但投影要轻，不制造课程页式强转化感。

## 13. 响应式与可访问性

小屏优先级：

1. 320/360 宽度下，首屏优先保住今日短语、`读一下` 和 `今天先说一句`。
2. 今日活动允许下滑出现。
3. 段落右侧辅助标签可以在小屏隐藏。
4. 不允许横向滚动。
5. 主要按钮不小于 44px，推荐 48px。

可访问性要求：

1. 播放按钮、主 CTA、活动卡片、花园入口、小禾入口和账号入口都有清晰语义。
2. 活动选中态不能只依赖颜色，需要有语义状态。
3. 完成 toast 使用局部状态播报。
4. 播放状态使用局部状态播报。
5. 不要把整页作为 live region，避免重渲染触发整屏播报。
6. 底部弹层需要可关闭，并且实现时要处理焦点返回。
7. 支持 TalkBack/VoiceOver 基础路径测试。
8. 支持减少动画设置。

## 14. 后续实现提示

实现 Home V23 时需要重点关注：

1. Shell 需要迁移到四 Tab：首页、发现、花园、成长。
2. Drawer 只放设置类入口，不重复主 Tab。
3. 小禾在首页通过内联 `问小禾` 和换场景入口可达，在 Practice 中保留低干扰 FAB。
4. Home 需要重做为“今日编排”结构，而不是复用现有 Practice 大卡片。
5. 今日短语、活动、花园痕迹应接入真实状态，不能只写静态文案。
6. 发音失败、小禾失败和同步失败要走用户语言，不暴露技术词。
7. 字体资源需要按 `DESIGN.md` 打包，不依赖 Google Fonts CDN。
8. 完成一句后需要触发轻 toast 和花园摘要，不做强制打卡。
9. 小禾临时练习必须保留来源字段，用于完成归因、toast 和花园摘要。
10. 自定义小禾场景需要保存用户输入或归一后的 `sceneLabel`，避免完成后显示泛化的“临时场景”。
11. Flutter 实现时检查底部导航安全区，避免活动卡片被导航栏视觉压住。

建议实现任务：

1. 实现 Home V23 的短语优先信息架构。
2. 迁移 Shell 到四 Tab + Drawer + 全局小禾 FAB。
3. 在 Practice 保留低干扰小禾入口。
4. 接入 `DESIGN.md` 字体和颜色 token。
5. 实现状态矩阵中的加载、空、失败和离线状态。
6. 实现练习完成后的 toast 与花园摘要。
7. 为“当前场景不对”提供低摩擦换场景入口。
8. 验证 320、360、430 宽度，以及 TalkBack/VoiceOver 基础路径。
