# Phase 41/42 Ritual Room — 句子光场设计合同

## 1. 设计结论

Phase 41/42 的 Ritual Room 采用「句子光场」方向。

它不是学习页、词卡页、任务页、编辑页、播放器页或带有完成感的
session 页面。它是一个安静托住父母当下动作的空间：

> 父母在真实育儿时刻打开这里，不需要学习界面，也不需要证明什么；
> 第一眼就得到一句现在能够对宝宝说的话。

系统级情绪底座是低压力、安静陪伴与柔和留白。这个底座可以随场景
轻微呼吸：

- 玩耍场景可以更明亮、更轻。
- 哭闹或抗拒场景可以更稳、更低饱和。
- 睡前场景可以更柔和、更安静。

变化只发生在色温、边缘线稿姿态、留白感和动效节奏。页面骨架、阅读
顺序、主句颜色和主句视觉权重始终不变。

## 2. 合同权威与范围

本文是 Phase 41/42 Ritual Room 的新视觉、交互、响应式、无障碍和验收
合同。

本文覆盖并替代 Phase 41 D.4.5 中以下旧呈现方向：

- 明显的内容卡片边界与卡片阴影
- 顶部 AppBar 式页面标题区
- 直接暴露在首屏的情境选项
- modal bottom sheet 式情境选择
- 视觉上接近短语卡或播放器的主句区域

本文不替代以下既有工程合同：

- Phase 41 Interaction Engine
- `ProductSnapshot` 作为完整产品真相
- Riverpod 单一可变会话节点
- typed input envelope
- 单调递增 revision
- 未知结果复用原事件 ID 的对账与幂等重试
- DTO → mapper → repository → domain → presentation 的依赖边界
- Phase 41 semantic firewall 与 Activation Governor 验证

Phase 41 已实现的交互能力可以继续作为运行基础；Phase 42 或后续计划负责
把本文设计落到 Flutter Android UI。不得为了视觉重做而把 interaction
engine 退化为静态 reaction-to-sentence lookup。

## 3. 产品承诺与不可动摇原则

### 3.1 主句是行动答案

英文主句是首屏绝对视觉中心。父母第一眼必须知道：

> 我现在可以这样对宝宝说。

页面不使用“推荐”“当前句子”“第几句”等标签解释主句地位。排版、留白
和明度关系本身建立主次。

### 3.2 插画是情绪容器

场景插画使用边缘亲子线稿，保留人物关系和当下动作，但不讲完整故事。
它可以从画布上方或侧边进入，不能进入主句核心阅读静区。

插画负责：

- 帮助父母确认自己身处哪个家庭场景
- 安顿情绪
- 保留真实亲子时刻的温度

插画不负责：

- 成为首屏主角
- 展示课程内容
- 描述完整叙事
- 判断或标记宝宝状态
- 提供任务、奖励或表现反馈

### 3.3 固定信息路径

首屏阅读路径始终是：

1. 英文主句
2. 简短中文意译
3. 一个动作时机
4. `听一下`
5. 情境校准入口
6. `先这样就好`

这条路径形成父母的肌肉记忆。任何场景变化、异步状态或屏幕尺寸适配都
不得改变顺序。

### 3.4 无卡片化的句子光场

主句不被装进明显的纸张卡、内容卡或功能面板。句子光场通过以下方式
建立清晰锚点：

- 主句字号与字重
- 主句周围完整静区
- 中央局部 2–4% 的柔和明度提升
- 插画进入光场前完成淡出
- 播放入口紧邻主句，但保持低强调

句子光场没有边框、阴影、圆角矩形轮廓或明确终点。

### 3.5 布局稳定，情绪微调

不同场景使用同一空间骨架。视觉变化必须“细微可感知”，不能强到像切换
另一个产品主题。

英文主句始终使用同一暖黑主文字，不能随场景改变颜色、权重或位置。

### 3.6 所有交互服务原位开口

播放、情境变化、失败恢复和辅助层收起都发生在原位。不得进入：

- 教学流程
- 句子比较
- 历史记录
- 表现反馈
- 完成总结
- session 收尾

## 4. 设备与响应式空间合同

### 4.1 验证视口

- `427×952dp`：当前 Pixel 9 Pro Android 模拟器的主验证视口
- `390×844dp`：compact Android 设计参考与 fallback 验证视口

两者都是验收视口，不是固定画布。实现必须使用 `SafeArea`、约束和比例
适配，不能用设备型号分支或固定像素坐标定位。

### 4.2 页面空间

SafeArea 内的页面由三个视觉层组成：

```text
Ritual Room
├─ 场景气氛层：约 20–24%，有最大高度约束
├─ 句子光场：弹性主区域，约 42–48%
└─ 安静控制层：折叠/展开共享的底部预留区，约 24–30%
```

比例用于表达优先级，不是硬切片。最终尺寸由可用高度、文本缩放和内容
约束共同决定。

### 4.3 大屏规则

Pixel 9 Pro 多出来的高度只用于：

- 增加主句上下留白
- 扩大句子光场的呼吸感
- 让气氛层与控制层之间更从容

不得用于：

- 增加模块
- 增加按钮
- 增加说明
- 增加插画叙事
- 放大插画使其成为主角
- 增加内容密度

### 4.4 Compact fallback

空间不足时按以下顺序收紧：

1. 装饰留白
2. 插画尺寸
3. 气氛层高度
4. 外围间距

不得压缩或移除：

- 英文主句
- 中文意译
- 动作时机
- `听一下`
- 情境校准入口
- 48dp 触控区域

### 4.5 底部控制区

情境控制层展开时：

- 只占用底部预留区
- 不推动主句
- 不覆盖主句阅读区
- 不压暗主句
- 不显示 modal 遮罩
- 不改变页面成为表单或独立流程

选项超过可用空间时，仅在控制区内部轻量滚动。

## 5. 颜色系统

Ritual Room 不使用传统“主色 + 强 CTA 色”结构。颜色只帮助父母看懂和
安定下来，不承担教学、激励、评价或完成语义。

| 角色 | 色值 | 合同 |
|---|---:|---|
| 暖纸背景 | `#FBF6EF` | 全屏基础画布 |
| 句子光场 | `#FFFDF9` | 无边界局部柔光 |
| 主文字 | `#302A26` | 英文主句；所有场景固定 |
| 次文字 | `#6D625B` | 中文意译 |
| 弱文字 | `#756A63` | 动作时机、场景标签、小型说明 |
| 安静青绿 | `#3F746B` | 播放、焦点、选中情境等辅助能力 |
| 柔和青绿面 | `#E4F0EC` | 极少量选中或聚焦反馈 |
| 温暖强调 | `#B9653B` | 非文本的小型状态点或焦点辅助 |
| 细分隔 | `#E2D9D1` | 底部控制区的轻微边界 |

颜色边界：

- 安静青绿不能成为大面积按钮或页面视觉中心。
- 温暖强调不能用于正文小字，因为它在暖纸背景上不满足正文 AA 对比。
- 温暖强调不得表达鼓励、奖励、结果、进度或完成。
- 选中、失败、加载不能只依赖颜色表达。
- 主句颜色和权重不得随场景变化。
- 高对比模式取消光场渐变，改用纯色层级。

对比度基线：

- `#756A63` 在 `#FBF6EF` 上约为 4.88:1。
- `#3F746B` 在 `#FBF6EF` 上约为 4.98:1。
- 正常文字和交互标签必须达到 WCAG AA。
- 分隔线和非文本控件边界至少满足非文本对比要求。
- 最终结果必须在真实 Flutter 渲染、两个目标视口和 Android 字体栅格化下
  再验证，不能只依赖色值计算。

## 6. 字体系统

字体不依赖在线服务。

- Android 首选本地 `Noto Sans` / `Noto Sans SC`
- 未捆绑字体时回退至系统 sans-serif
- 不引入衬线、装饰或绘本字体

| 内容 | 427×952 主验证版 | 390×844 compact |
|---|---:|---:|
| 英文主句 | 34–36sp / 600 / 1.25 | 30–34sp / 600 / 1.25 |
| 中文意译 | 16sp / 400 / 1.55 | 15–16sp / 400 / 1.55 |
| 动作时机 | 13sp / 600 / 1.4 | 13sp / 600 / 1.4 |
| 辅助入口 | 15sp / 400–600 | 15sp / 400–600 |
| 场景标签 | 13sp / 600 | 13sp / 600 |

主句规则：

- 最多自然换行三行作为默认内容目标
- 不截断
- 不使用省略号隐藏内容
- 不按视口宽度连续缩放字体
- 长句优先换行和允许页面纵向滚动，不缩成弱小文字

## 7. 场景情绪系统

`RitualAtmosphereLayer` 只能消费外部传入的场景气质 token。它不得读取
宝宝行为、交互历史或业务错误，自行推断情绪。

| 气质 token | 背景呼吸 | 线稿姿态 | 动效节奏 |
|---|---|---|---|
| `everydayCalm` | 暖纸米白 | 动作自然靠近 | 180–220ms |
| `gentlyLively` | 略偏暖黄，明度稍高 | 姿态打开、线条轻快 | 150–190ms |
| `groundedSoothing` | 饱和度降低，偏柔灰米色 | 姿态收拢、重心降低 | 220–280ms |
| `bedtimeQuiet` | 柔和暖灰杏色 | 动作最小、留白更多 | 260–320ms |

场景气质不是宝宝状态标签，也不是 child-state classifier。token 的来源
必须是经过产品批准的场景内容元数据，或由交互 snapshot 明确提供的受控
presentation token。展示层不得从原始情境文字、宝宝行为或错误类型推断
token；一次普通情境提交也不得在没有明确 token 的情况下自行改变房间气氛。

禁止抖动、弹跳、粒子、视差、循环呼吸动画、奖励动效和插画表演。

## 8. 页面与组件结构

推荐的 Flutter 结构：

```text
RitualRoomScreen
└─ SafeArea
   └─ LayoutBuilder
      └─ Stack
         ├─ RitualAtmosphereLayer
         ├─ RitualSentencePlane
         └─ RitualContextDock
```

`Stack` 只用于层次表达，不能决定 TalkBack 顺序。语义树必须由独立、线性
的内容结构控制。

### 8.1 `RitualAtmosphereLayer`

职责：

- 暖纸背景
- 无边界句子光场
- 边缘亲子线稿
- 场景气质 token 的视觉投影

约束：

- `IgnorePointer`
- 排除在语义树之外
- 不读取 Room 业务状态
- 不判断宝宝处于何种状态
- 插画有明确尺寸上下限
- 插画不得侵入主句阅读静区

### 8.2 `RitualSentencePlane`

职责：

- 渲染英文主句
- 渲染简短中文意译
- 渲染一个动作时机
- 承载低强调播放入口

它必须消费一个不可变话术 snapshot。英文、中文和动作时机来自同一
snapshot，并作为一个原子内容单元切换。不得出现英文已更新而中文或动作
时机仍停留在旧内容的中间态。

提交、失败、未知结果和音频加载都不能替换、遮挡或拿走当前 snapshot。

### 8.3 `RitualListenControl`

播放状态与 Room 业务状态分离：

```text
available
loading
playing
paused
failure
```

视觉合同：

- 图标加文字
- 默认文案 `听一下`
- 播放中显示 `暂停`
- 最小 48×48dp 触控范围
- 不显示波形、时长、进度条或播放器面板
- 加载只替换图标位置为小型进度环
- 播放结束后静默恢复

音频失败文案：

> 暂时听不了，你也可以直接照着说。

音频失败不影响主句、情境校准或 Room snapshot。

### 8.4 `RitualContextDock`

它是底部安静停靠层，不是 `showModalBottomSheet`，也不是独立 route。

折叠态只露出低压力入口，例如：

> 想让这句话更贴近一点吗？

可配合轻量辅助文字：

> 轻触告诉我

展开态：

- 标题：`宝宝现在怎么了？`
- 辅助说明：`选一个最接近的就好`
- 2–5 个中性文本情境
- `收起`
- `先这样就好`

选项是当下情境校准，不是宝宝表现记录、诊断、判断题或问卷。

### 8.5 `RitualContextChoices`

- 使用 `Wrap` 或自适应单列
- 无阴影、无成功图标、无勾号
- 选中态使用安静青绿边框、浅色底和文字语义
- 相邻触控目标间距至少 8dp
- 选择后只锁其他情境选项和重复提交
- `收起`、Android 返回键和 `先这样就好` 始终可用

父母不能被困在一次请求里。

### 8.6 `RitualTransientNotice`

只承载当前控制层里的临时状态：

- 正在调整
- 调整说明
- 可恢复失败
- 未知结果
- 重试或对账

它不写入历史，不成为总结，不建立完成或结果语义。

## 9. 交互状态与低压力 Room loop

Ritual Room 是一个持续稳定的 Room loop，不是 session flow、form flow 或
player flow。

```text
看见一句话
  → 可选听一下
  → 可选展开情境校准
  → 原位获得更贴近的一句话
  → 收起辅助层
```

局部状态可以并发，但不能互相污染：

```text
Room snapshot: stable immutable current utterance
├─ audio: available | loading | playing | paused | failure
└─ dock: collapsed | expanded
   └─ request: idle | submitting | recoverableFailure | unknownOutcome
```

约束：

- 音频播放与 Dock 展开可以并存。
- 情境提交不停止音频。
- 收起 Dock 不取消已提交请求。
- Dock 收起后请求完成，主句仍可原位更新。
- 每个局部状态只影响自己的 UI。
- 主句始终是稳定可用的行动答案。

## 10. 主句更新

情境选择后：

1. 锁住情境选项与重复提交。
2. 保持 `收起`、Android 返回键和 `先这样就好` 可用。
3. 在控制层显示：

   > 正在让这句话更贴近一点…

4. 当前主句、中文和动作时机保持完整可读。
5. 新 snapshot 返回后，Dock 自动收起。
6. 旧话术 snapshot 在原位置淡出，新 snapshot 原位淡入。
7. 短暂显示只解释“说法调整”的说明。

允许的说明示例：

- `换成更安抚一点的说法`
- `贴近想自己来的时刻`

禁止的说明：

- 对宝宝状态作诊断
- 解释宝宝为什么这样表现
- 使用行为评估或教学语气
- 暗示系统对宝宝作出心理、能力或服从性判断

说明约 2–3 秒后自然淡出，不进入历史。

## 11. “先这样就好”

`先这样就好` 是降噪操作，不是完成、退出、保存或 session 结束。

行为：

- Dock 展开时：收起 Dock，并把阅读焦点还给当前主句。
- 有临时说明时：允许临时说明自然退场，不生成额外反馈。
- 主句刚更新时：保留更新后的 snapshot。
- 正在播放时：不强制停止。
- 请求提交中：收起辅助层，但不取消请求。
- Dock 已折叠时：确保所有辅助层已收起，把阅读焦点还给当前主句；不触发
  导航、完成、保存或分析事件。

Android 系统返回键与它不同：

- Dock 展开时，系统返回键优先收起 Dock。
- Dock 折叠且 Room 稳定时，系统返回交给上层导航。

## 12. 失败、未知结果与对账

所有异常遵循同一原则：

> 系统永远不拿走父母手里的当前可说句子。

这条原则从首个可用 snapshot 出现后生效。初次加载尚无可用 snapshot 时，
页面仍使用同一空间骨架：保留气氛层、句子光场的静区和底部安全区，在主句
位置使用低强调的 `正在准备这句话…`，不显示伪造句子、卡片 skeleton 或
全屏中央 spinner。

| 状态 | 局部反馈 | 保留能力 |
|---|---|---|
| 音频加载 | 图标位置轻量进度环 | 主句、Dock、收起 |
| 音频失败 | `暂时听不了，你也可以直接照着说。` | 重试、校准、收起 |
| 情境提交中 | `正在让这句话更贴近一点…` | 播放、收起、返回 |
| 可恢复失败 | `这次没有换好，刚才那句话还可以继续用。` | 原请求重试 |
| 未知结果 | `刚才的调整还没有确认。` | 原事件 ID 对账 |
| 初始加载失败 | 安静错误文案与 `再试一次` | 保持空间骨架，不显示空白或技术错误 |

未知结果边界：

- `再试一次` 必须复用原始事件 ID。
- 重试语义是查询、对账或幂等重放原请求。
- 不得创建新的独立情境请求。
- 不得重复推进 revision。
- 对账成功后返回同一已接受结果。
- 未知状态期间锁住新的情境提交，但不锁收起、返回或播放。

失败 UI 禁止大面积红色、警告插画、错误卡片和阻断弹窗。

## 13. 动效与减少动态效果

正常模式：

- 主句切换使用透明度和极轻位移
- 句子更新 150–320ms，取决于场景气质 token
- Dock 展开与收起 150–250ms
- 不使用尺寸突变、弹簧或弹跳

系统开启减少动态效果时：

- 取消位移
- 取消 Dock 滑动
- 使用不超过 100ms 的淡化或即时替换
- 不运行循环呼吸、视差、缩放或插画动画

状态必须同时通过文字、图标和语义表达，不能只靠动画。

## 14. TalkBack 与语义合同

视觉层可以使用 `Stack`，语义顺序必须固定为：

1. 英文主句
2. 中文意译
3. 动作时机
4. `听一下`
5. 情境校准入口
6. `先这样就好`

实现要求：

- 使用明确语义容器和排序键。
- 主句作为完整句子朗读，不逐词拆分。
- 动作时机读作：`说这句话的时机：<动作时机>`。
- 播放控制读作：`播放这句话`、`正在加载语音`或`暂停播放`。
- 情境选项读作普通按钮。
- 选中提交时可读作：`<情境>，已选择，正在调整说法`。
- 临时失败和未知结果使用一次性 live region。
- live region 不抢焦点、不循环播报。
- 主句更新后宣告：`说法已调整：<新主句>`。
- 异步更新不得把焦点强制跳回页面顶部。
- 插画、光场、分隔线和装饰元素不进入语义树。

## 15. 文字放大

验证范围：

- `1.0×`：视觉基准
- `1.3×`：必须保持完整首屏布局和 48dp 触控目标
- `1.5×–2.0×`：允许页面纵向滚动

任何缩放下都不得：

- 裁切内容
- 文本重叠
- 横向溢出
- 产生不可达操作
- 改变语义顺序
- 隐藏中文或动作时机

嵌套滚动需要明确边界：页面纵向滚动负责放大后的主内容可达性；Dock 内部
滚动只负责情境选项。不得让两个滚动区争夺主要手势。

## 16. Flutter 与架构边界

### 16.1 技术栈

- Flutter
- Android portrait-first
- Material 3 基础能力
- Riverpod 仅用于既有 app composition 与唯一会话节点
- 本地 `ThemeExtension` 提供颜色、间距、字体和场景气质 token

### 16.2 禁止的实现捷径

- 无 AppBar
- 无卡片化主句
- 无 modal bottom sheet
- 无强 CTA
- 无第二个 Room controller、Notifier 或 ViewModel
- 无 DTO、fixture 或 mock API 进入 presentation
- 无 presentation 自行组合英文、中文和动作时机
- 无展示层根据宝宝行为推断情绪 token
- 无用多个布尔值复制或拆散现有状态真相

### 16.3 数据边界

运行路径保持：

```text
data source
  → transport DTO
  → mapper
  → repository
  → immutable domain/ProductSnapshot
  → app composition
  → presentation values and callbacks
```

展示层只消费领域模型和当前 Room snapshot。正常运行时可见内容不得来自
widget 常量、测试 fixture 或 mock implementation import。

### 16.4 本地 UI 文案

通用 UI chrome 文案应进入 Flutter localization 资源，例如：

- `听一下`
- `暂停`
- `收起`
- 重试与无障碍状态说明

场景、主句、中文意译、动作时机、情境选项和情境调整说明由内容或交互
snapshot 提供，不硬编码在 widget 中。

## 17. 测试合同

### 17.1 组件与 widget 测试

必须覆盖：

- `RitualSentencePlane` 原子渲染同一 snapshot 的英文、中文和动作时机。
- 提交期间旧 snapshot 始终可读。
- 音频状态只更新播放局部 UI。
- Dock 折叠、展开和内部滚动不改变主句核心几何位置。
- 提交只锁情境选项，不锁 `收起`、返回键或 `先这样就好`。
- Dock 收起后，已完成请求仍可更新主句。
- 未知结果复用原事件 ID。
- 对账成功不重复推进 revision。
- Android 返回键在展开态只收起 Dock。
- `先这样就好` 不触发完成、保存、退出或分析事件。
- 替换注入的领域内容后 UI 同步变化，证明展示层未硬编码话术。
- `RitualAtmosphereLayer` 不读取 Room 业务状态。

### 17.2 无障碍测试

- 固定 TalkBack 语义顺序。
- 装饰插画不进入语义树。
- 所有触控目标至少 48×48dp。
- 相邻操作至少间隔 8dp。
- 播放语义随状态变化。
- 临时状态只宣告一次。
- 状态不只依赖颜色。
- 文本和控件达到 WCAG AA。
- `1.3×` 和 `2.0×` 不裁切、不重叠且操作可达。

### 17.3 截图与 golden

每个关键状态分别生成 `427×952dp` 和 `390×844dp` 视觉基线：

- 稳定主状态
- Dock 展开
- 情境提交中
- 主句更新完成
- 可恢复失败
- 未知结果
- 音频加载
- 音频失败
- `1.3×` 文字
- 减少动态效果

golden 不把动态内容锁成错误的像素级产品常量。视觉审查重点：

- 主句是否仍是第一视觉中心
- 插画是否离开主句静区
- Dock 是否保持非模态
- 大屏是否只增加呼吸感
- compact 是否保留全部行动答案
- 是否出现卡片、表单、播放器或任务面板感

### 17.4 设备 UAT

主环境：Pixel 9 Pro 模拟器 `427×952dp`。

补充环境：`390×844dp` compact Android 视口。

UAT：

1. 打开 Room，第一眼可以定位英文主句。
2. 播放、暂停、加载和失败不移动或拿走主句。
3. 展开 Dock 后主句仍完整可见。
4. 提交情境后旧句持续可用。
5. 提交期间可以收起 Dock 或使用系统返回键。
6. 新 snapshot 的英文、中文和动作时机原子更新。
7. 模拟服务端已接受但响应丢失，进入未知结果。
8. 使用原事件 ID 对账，返回同一结果且 revision 不重复推进。
9. 连续两次不同情境调整后，Room 身份和阅读路径不变。
10. `先这样就好` 只降噪，不产生完成或退出反馈。
11. TalkBack 可按固定顺序完成整个 Room loop。
12. `1.3×` 与 `2.0×` 文字缩放下功能仍可达。
13. 减少动态效果开启后，不出现位移、滑动或循环动画。

## 18. 旧产品语义防火墙

以下语义不得进入 `mobile_v2/lib` 运行时代码、正常 mock 数据、可见 UI、
截图 golden 或用户可见文案：

- 课程、练习、任务、打卡
- 进度、得分、积分、连胜、解锁
- 正确、完成、表现、达标
- 下一句、继续下一句
- 宝宝是否学会、是否照做或是否完成动作
- 宝宝状态诊断、行为评分或服从性记录
- 完成页、总结页、历史比较
- 奖杯、星星、徽章、勾选、成长植物
- AI、模型、置信度、生成结果等技术语言

验证器可以在隔离的 negative fixture 或专用负例测试样本中故意包含被禁
语义，以证明防火墙有效。负例必须：

- 明确位于测试或 verifier fixture 路径
- 不被应用运行时注册或加载
- 不进入正常 mock payload
- 不进入截图 golden
- 不进入任何用户可见界面
