# Flutter Mobile Growth 成长页交互结论

日期：2026-05-28
状态：Growth 子设计已确认（待合入整体 QA 迭代设计）

## 1. 读者与读完后动作

本文件写给产品、设计和 Flutter 实现工程师。

读完后，读者应该能够：

1. 判断 Growth 页和 Garden 花园页的职责边界。
2. 按 Growth 的信息架构实现 Flutter 成长页。
3. 为加载、空态、离线等状态设计用户可见反馈。
4. 验收成长页是否符合 `DESIGN.md` 的 Warm Paper Kindness 方向。

本文件不是实现计划，也不直接批准生产代码改动。进入实现前仍需要拆分任务、确认数据契约和测试范围。

## 2. 背景与目标

Garden 花园页展示的是"我到底说过哪些话"——每一条痕迹的完整上下文。但家长也需要看到一个更宏观的画面：我一共说了多少句、覆盖了哪些照护场景、坚持了多久。Growth 成长页就是承载这个宏观视角的地方。

Growth 的定位是"真实练习的温暖回顾"：家长看到的不是数据仪表盘，而是自己陪伴宝宝成长的真实轨迹。

目标：

1. 用温暖的方式展示练习总量和覆盖范围。
2. 里程碑庆祝真实的育儿成就，不是游戏化奖励。
3. 数据可视化克制、亲切，不像健康报告或学习仪表盘。
4. 让家长感到"我确实在做这件事"，而不是"我完成了多少任务"。

非目标：

- 不做连续天数、打卡 streak 或排行榜。
- 不做分数、等级或经验值系统。
- 不做复杂的图表或交互式数据探索。
- 不做社交对比功能。
- 不使用 emoji 或儿童化装饰。
- 不做数据导出或分享功能。

## 3. 页面职责边界

Garden 花园页承载：每条练习痕迹的完整上下文、按日分组的时间线、场景分布。

Growth 成长页承载：

1. 练习总量摘要（说了多少句、覆盖多少场景、累计多少天）。
2. 场景覆盖进度（哪些场景练习过、哪些还没有）。
3. 里程碑列表（真实育儿成就）。
4. 最近活跃趋势（本周/本月的练习节奏）。

关键边界：Garden 回答"我说过什么"，Growth 回答"我做得怎么样"。

## 4. 信息架构

成长页首屏优先级：

1. 页面标题。
2. 练习总量摘要卡片。
3. 场景覆盖进度。
4. 里程碑列表。
5. 最近活跃趋势。

结构：

```text
顶部栏
  返回 / 成长

总量摘要
  你已经对宝宝说了 47 句英语。
  覆盖了 6 个照护场景，坚持了 18 天。

场景覆盖
  喂饭     ████████░░  12 句
  睡前     ██████████  15 句
  洗澡     ██████░░░░   8 句
  出门     ████░░░░░░   5 句
  换尿布   ████░░░░░░   4 句
  喝水     ██░░░░░░░░   3 句

里程碑
  ✓ 第一句英语        5月10日
  ✓ 第一次睡前场景    5月12日
  ✓ 累计10句          5月18日
  ✓ 覆盖3个场景       5月20日
  ○ 累计50句          还差3句

最近活跃
  本周：8 句
  上周：12 句
```

设计要求：

1. 总量摘要卡片是页面第一视觉锚点。
2. 场景覆盖使用轻量进度条，不使用饼图或柱状图。
3. 里程碑列表简洁，已完成和未完成有清晰区分。
4. 最近活跃趋势放在底部，是最轻的模块。
5. 页面底部留足安全区空间。

## 5. 总量摘要

总量摘要是页面顶部的温暖回顾卡片。

内容：

1. 主文案：一句完整的回顾句子，如"你已经对宝宝说了 47 句英语。"
2. 辅助信息：覆盖场景数和坚持天数。
3. 数字使用 DM Sans 的 tabular-nums 特性，与中文自然混排。

设计要求：

1. 总量摘要使用 --bg-surface 背景 + --shadow-md 轻阴影。
2. 主文案中的数字使用 --english 颜色高亮，与英文短语高亮一致。
3. 辅助信息使用 --text-secondary 颜色，不抢主文案视觉重心。
4. 卡片不使用装饰性图标或插画。
5. 文案语气温暖、鼓励，但不做过度庆祝。

文案规则：

- 主文案格式：`你已经对宝宝说了 {N} 句英语。`
- 辅助信息格式：`覆盖了 {M} 个照护场景，坚持了 {D} 天。`
- 零状态：`开始说第一句后，这里会记录你的成长。`

## 6. 场景覆盖

场景覆盖展示每个照护场景的练习进度。

内容：

1. 场景名称。
2. 进度条（该场景练习句数占总句数的比例）。
3. 该场景的练习句数。

展示规则：

1. 只显示有练习记录的场景。
2. 按练习句数降序排列。
3. 进度条使用 --english 颜色填充，--bg-sunken 作为轨道。
4. 进度条高度 4px，与全局 ProgressBar 组件一致。

设计要求：

1. 场景覆盖区域使用轻标题分隔，不使用卡片包裹。
2. 每个场景条目之间有合理间距。
3. 进度条宽度占满可用空间。
4. 数字右对齐，使用 tabular-nums。
5. 不显示百分比数字，避免过度量化。
6. 未覆盖的场景不显示，不做"待解锁"暗示。

## 7. 里程碑

里程碑庆祝真实的育儿成就。

里程碑类型：

1. 第一句英语：完成第一次练习。
2. 第一次场景覆盖：首次在某个场景练习。
3. 累计句数里程碑：10 句、25 句、50 句、100 句。
4. 场景覆盖里程碑：覆盖 3 个、5 个场景。
5. 坚持天数里程碑：7 天、14 天、30 天。

展示规则：

1. 已完成里程碑显示 --success 颜色的对勾图标和完成日期。
2. 未完成里程碑显示空心圆圈和"还差 N 句/天/个场景"。
3. 里程碑按时间顺序排列，已完成的在前，未完成的在后。
4. 最多显示 8 个里程碑，更多时显示"查看更多"（Phase 2）。

设计要求：

1. 里程碑列表使用简洁的列表样式，不使用卡片。
2. 已完成和未完成的视觉区分清晰但克制。
3. 未完成里程碑使用 --text-muted 颜色，不抢已完成的视觉重心。
4. 日期使用小号 --text-muted 文字。
5. "还差"文案温和，不做催促语气。

文案规则：

- 已完成：`✓ {里程碑名称}` + `{日期}`
- 未完成：`○ {里程碑名称}` + `还差 {N} {单位}`
- 示例：`○ 累计50句` + `还差3句`

## 8. 最近活跃

最近活跃是页面底部的轻趋势模块。

内容：

1. 本周练习句数。
2. 上周练习句数。
3. 简单的趋势指示（本周比上周多/少/持平）。

展示规则：

1. 使用两行简单数字，不做图表。
2. 趋势指示使用温和文案，不做上升/下降箭头。
3. 不显示更早的历史数据。

设计要求：

1. 最近活跃区域使用 --bg-sunken 背景，与场景分布样式一致。
2. 数字使用 DM Sans + tabular-nums。
3. 趋势文案使用 --text-secondary 颜色。
4. 整体区域不高于 80px，保持轻量。

文案规则：

- 多了：`本周比上周多说了 {N} 句。`
- 少了：`本周稍有减少，没关系。`
- 持平：`和上周差不多，保持就好。`
- 零状态：`开始练习后，这里会显示你的活跃节奏。`

## 9. 空态

首次进入成长页或尚无练习记录时的空态。

空态内容：

1. 轻插画或图标（不使用 emoji）。
2. 主文案：`你的成长还没有开始。`
3. 辅助文案：`说完第一句英语后，这里会记录你的陪伴轨迹。`
4. 主按钮：`回到首页说一句`

设计要求：

1. 空态居中显示。
2. 文案温暖但不催促。
3. 主按钮使用 --accent 颜色。
4. 空态时隐藏场景覆盖、里程碑和最近活跃区域。

## 10. 加载态与离线态

加载态：

1. 保留顶部导航栏。
2. 总量摘要卡片显示骨架屏。
3. 场景覆盖和里程碑区域显示轻骨架条。
4. 不显示空白区域或加载 spinner。

离线态：

1. 成长数据来自本地缓存，不阻断浏览。
2. 顶部显示轻提示：`离线时看到的是上次同步的数据。`
3. 所有模块正常展示缓存数据。

## 11. 视觉系统要求

Growth 必须对齐 `DESIGN.md`。

字体：

1. 数字使用 DM Sans 的 tabular-nums 特性。
2. 中文 UI 使用 PingFang SC / Noto Sans SC / Microsoft YaHei。
3. 英文 UI 使用 DM Sans。

颜色：

1. 主背景：`#FFF8F0`（--bg-base）。
2. 摘要卡片背景：`#FFFFFF`（--bg-surface）。
3. 数字高亮：`#3B8577`（--english）。
4. 进度条填充：`#3B8577`（--english）。
5. 进度条轨道：`#F5F0EB`（--bg-sunken）。
6. 里程碑完成：`#6B8F5E`（--success）。
7. 里程碑未完成：`#8A7D76`（--text-muted）。
8. 趋势背景：`#F5F0EB`（--bg-sunken）。

视觉要求：

1. 不使用紫色、蓝紫渐变或高饱和配色。
2. 不使用 emoji 或装饰性图标。
3. 不使用饼图、柱状图或复杂图表。
4. 进度条保持 4px 高度，不做粗进度条。
5. 阴影克制（--shadow-md 仅用于总量摘要卡片）。
6. 数字与中文混排时保持自然基线对齐。

## 12. 响应式与可访问性

小屏优先级：

1. 320/360 宽度下，总量摘要卡片保持完整。
2. 场景覆盖进度条不截断。
3. 里程碑列表保持可读。
4. 不允许横向滚动。
5. 主要按钮不小于 44px。

可访问性要求：

1. 进度条需要有关联的文字说明（场景名 + 句数）。
2. 里程碑状态不能只依赖颜色，需要有图标和文字。
3. 数字需要有关联的上下文说明。
4. 空态按钮有清晰语义。
5. 支持 TalkBack/VoiceOver 基础路径测试。
6. 支持减少动画设置。

## 13. 后续实现提示

实现 Growth 时需要重点关注：

1. 成长数据来自本地 Isar 数据库，需要聚合查询。
2. 总量摘要需要实时计算：总句数、覆盖场景数、坚持天数。
3. 场景覆盖需要按场景分组统计。
4. 里程碑需要预定义规则并实时判定。
5. 最近活跃需要按周统计。
6. 加载态骨架屏需要模拟真实布局。
7. 离线态依赖本地缓存。
8. 数字与中文混排时的 Flutter TextSpan 处理。

建议实现任务：

1. 实现总量摘要的聚合查询和展示。
2. 实现场景覆盖的分组统计和进度条。
3. 实现里程碑规则引擎和列表展示。
4. 实现最近活跃的周统计。
5. 实现空态、加载态和离线态。
6. 验证 320、360、430 宽度。

## 14. 已确认视觉原型

最终确认原型：

- `qa-mobile-growth-v1-warm-growth.html`

关键调整：

1. 成长页从数据仪表盘改为温暖回顾。
2. 总量摘要使用完整句子，不是数字堆叠。
3. 场景覆盖使用轻进度条，不做复杂图表。
4. 里程碑庆祝真实成就，不做游戏化奖励。
5. 最近活跃使用温和趋势文案，不做升降箭头。
6. 数字使用 DM Sans + tabular-nums 保持对齐。
7. 颜色和字体对齐 `DESIGN.md`。

## 15. 本轮不包含

本文件不定义以下内容：

1. 成长页与后端同步的接口契约。
2. 里程碑规则的完整定义（仅列出典型类型）。
3. 数据导出或分享功能。
4. 复杂的数据可视化或交互式图表。
5. 社交对比功能。
6. 多宝宝切换。

这些内容需要在对应子设计或实现计划中继续确认。
