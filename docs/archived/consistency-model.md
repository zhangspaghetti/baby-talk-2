# 一致性模型

## 概述

BabyTalk 后端在不同场景下采用不同的一致性策略。本文档明确强一致 vs 最终一致的边界，以及 saga/outbox 的使用范围。

## 一致性分类

| 场景 | 一致性要求 | 策略 | 原因 |
|---|---|---|---|
| 用户登录/登出 | 强一致 | 同步事务 | 安全关键，token 状态必须即时一致 |
| RBAC 权限变更 | 强一致 | 同步事务 | 权限变更必须即时生效 |
| 儿童语音数据删除 | 强一致 | 同步事务 | 合规要求，删除必须即时生效 |
| 知识库内容同步 | 最终一致 | Outbox + 异步 | 允许短暂不一致，吞吐优先 |
| 练习记录上报 | 最终一致 | Outbox + 异步 | 允许短暂不一致，离线优先 |
| Mentor 对话历史 | 最终一致 | 异步写入 | 允许短暂不一致 |
| 家庭组成员变更 | 强一致 | 同步事务 | 多人共享状态，必须即时一致 |
| 分发统计数据 | 最终一致 | 定时聚合 | 统计数据允许延迟 |

## 强一致场景实现

### 登录/登出

```
用户请求 → AdminAuthService.login()
         → 数据库事务：写入 session + refresh token
         → 返回 token pair
         → 所有操作在同一事务内，要么全部成功，要么全部回滚
```

### RBAC 权限变更

```
管理员请求 → AdminRbacService.createRole()
           → 数据库事务：写入角色 + 授权
           → 权限立即生效（无缓存延迟）
           → 下次请求即使用新权限
```

## 最终一致场景实现

### 知识库同步（Outbox 模式）

```
1. 写入主表 + outbox 表（同一事务）
2. 异步消费者轮询 outbox
3. 消费成功后标记 outbox 记录为已处理
4. 失败重试（指数退避，最多 3 次）
```

### 练习记录上报（客户端离线优先）

```
1. 客户端本地存储练习记录
2. 网络恢复后批量上报
3. 服务端去重（基于 eventKey）
4. 返回 acceptedCount / duplicateCount
```

## Saga 使用范围

| 场景 | Saga 类型 | 补偿操作 |
|---|---|---|
| 跨服务数据同步 | 编排式 Saga | 撤销已写入的数据 |
| 批量知识库导入 | 编排式 Saga | 删除已导入的记录 |

## Outbox 使用范围

| 场景 | Outbox 表 | 消费者 | 重试策略 |
|---|---|---|---|
| 知识库变更通知 | knowledge_outbox | 索引服务 | 指数退避，3 次 |
| 练习事件上报 | practice_event_outbox | 统计服务 | 指数退避，3 次 |

## 客户端一致性

### 离线优先策略

- 练习记录：本地存储 → 网络恢复后批量同步
- 用户偏好：本地存储 → 网络恢复后合并
- 家庭组状态：实时同步 → 离线只读

### 冲突解决

- 练习记录：基于 eventKey 去重，服务端为准
- 用户偏好：Last-Write-Wins（基于 timestamp）
- 家庭组状态：服务端为准，客户端只读
