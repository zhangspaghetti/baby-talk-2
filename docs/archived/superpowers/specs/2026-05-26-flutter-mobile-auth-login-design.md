# Flutter Mobile 登录/注册页面交互结论

日期：2026-05-26  
状态：Auth 子设计已确认（待合入整体 QA 迭代设计）

## 1. 背景与目标

本轮 QA 发现移动端登录页面信息过多、结构不清，并缺少关键登录能力：

1. 验证码登录没有明确的“发送验证码”按钮。
2. 发送验证码前没有人机校验入口。
3. 密码登录、注册、忘记密码/重置密码链路不完整。
4. 页面文案需要更克制，避免一次性展示过多说明。

目标是让登录页成为一个清晰、可操作、移动端友好的入口，覆盖验证码登录、密码登录、注册和重置密码。

非目标：

- 本文件不定义最终视觉像素稿之外的生产实现细节。
- 本文件不直接修改 Flutter 或后端代码。
- 不在登录首屏暴露复杂安全说明或技术术语。

## 2. 已确认交互方案

采用“渐进披露”的登录页结构：

1. 顶部保留 BabyTalk 品牌与一句简短说明。
2. 主操作区使用三种入口：验证码登录、密码登录、注册。
3. 每个入口只展示当前必要字段，避免所有输入项同时出现。
4. 人机校验只在用户点击“发送验证码”后出现，使用底部弹层承载。
5. 验证码输入只在人机校验通过、验证码已发送后出现。

## 3. 验证码登录

流程：

1. 用户输入手机号。
2. 点击“发送验证码”。
3. 打开 CAPTCHA / 人机校验底部弹层。
4. 校验通过后发送验证码。
5. 页面展示验证码输入、倒计时、重新发送状态。
6. 用户输入验证码后登录。

设计要求：

- 手机号和验证码使用数字键盘。
- 验证码支持自动填充、粘贴和视觉分格。
- 重新发送需要倒计时，避免重复请求。
- 错误提示使用用户能理解的语言，不暴露接口名、技术码或内部异常。

## 4. 密码登录

流程：

1. 用户输入手机号/邮箱和密码。
2. 点击“登录”。
3. 登录失败时展示明确、克制的错误信息。
4. 点击“忘记密码？”进入重置密码流程。

已确认修正：

- “忘记密码？”不能只是静态链接，也不能回到验证码登录。
- 点击后进入独立的“重置密码”页面或等价的重置流程状态。

## 5. 注册

流程：

1. 用户进入注册入口。
2. 输入手机号。
3. 点击“发送注册验证码”。
4. 打开 CAPTCHA / 人机校验底部弹层。
5. 校验通过后展示验证码输入和密码设置。
6. 用户完成注册后进入应用。

设计要求：

- 注册和登录状态要视觉上区分，避免用户误以为自己正在登录已有账号。
- 服务条款和隐私协议保持可见但不压迫主任务。
- 注册失败时说明是手机号已存在、验证码错误、密码不符合要求，还是网络问题。

## 6. 重置密码

流程：

1. 从密码登录页点击“忘记密码？”。
2. 进入“重置密码”。
3. 输入手机号/邮箱。
4. 点击“发送重置验证码”。
5. 打开 CAPTCHA / 人机校验底部弹层。
6. 校验通过后展示验证码输入。
7. 验证通过后设置新密码。
8. 完成重置后回到登录态；推荐直接登录并进入应用。

设计要求：

- 重置密码不和注册混用同一套文案。
- 验证码、倒计时、重发限制与登录验证码一致。
- 新密码与确认密码需要即时校验。

## 7. 后端契约影响

后续实现计划需要评估或补齐以下能力：

1. Auth challenge 创建接口需要区分用途：`login`、`register`、`reset_password`。
2. 发送验证码前需要提交 CAPTCHA proof / token。
3. 验证接口需要能根据 challenge 用途返回对应结果。
4. 密码登录、注册设置密码、重置密码接口需要和现有 auth 流程对齐。
5. 所有认证失败都需要返回可映射为用户语言的错误原因。

## 8. 可访问性与移动端要求

1. 所有主要按钮触控目标不小于 44px。
2. 输入框、验证码格、CAPTCHA 弹层、倒计时和错误提示需要有语义标签。
3. 支持 TalkBack/VoiceOver 读取当前流程状态。
4. CAPTCHA 不应阻断无障碍用户；后续实现需要选择可访问方案或提供等价校验路径。
5. 页面应在小屏幕上保持主要按钮可见，不依赖超长滚动才能完成登录。

## 9. 已确认视觉原型

视觉伴随原型：

- V10：`qa-mobile-auth-v10-reset-password.html`，确认忘记密码进入重置密码流程。

后续整体 QA 迭代设计应引用本文件作为 auth 子设计结论。
