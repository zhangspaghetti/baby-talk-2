# Flutter Mobile Home A/B Prototype - Refined Design Spec

日期：2026-05-28
状态：A/B 原型细化版（用于浏览器可点击用户测试）

## 1. 目标与背景

本文件是 Home A/B 原型测试设计的细化规格，基于 2026-05-26 的 A/B 测试设计文档和 Home V23 确认规格。目标是在进入 Flutter 实现前，通过浏览器可点击原型验证两个方向的可用性差异。

两个方向：

- **A: Plan-led V23 基线** — 延续当前 Home V23 结构，今日短语为主计划卡片。
- **B: Scene-mentor 方向** — 让页面感觉像真实照护时刻的陪伴，小禾和当前亲子场景更突出。

B 是推荐方向。A 作为可用性基线，用于区分"更好的概念"和"更清晰的常规布局"。

## 2. 测试用户画像

本轮测试对象：**已完成 onboarding 的回归家长**。

本轮不测试：首次打开理解、onboarding、账号设置、离线失败恢复。

## 3. 共享内容数据

使用真实的中文家长面向文案。避免通用占位文本。

默认场景：

| 字段 | 值 |
|------|-----|
| 场景 | 睡前收玩具 |
| 英文短语 | `Let's put it back.` |
| 中文释义 | 我们把它放回去吧。 |
| 家长动作 | 一边把玩具放回盒子，一边轻轻说给宝宝听。 |
| 小禾说明 | 这句适合睡前收尾，不像命令，更像邀请宝宝一起完成。 |

临时场景：

| 场景 | 小禾建议短语 | 中文释义 | 小禾说明 |
|------|-------------|---------|---------|
| 宝宝不肯睡 | `Time to sleep.` | 该睡觉了 | 降低声音，不讲长道理，轻轻拍着说。 |
| 洗澡时哭了 | `It's okay.` | 没关系的 | 先安抚情绪，声音放柔，不要急着擦干。 |
| 要出门但宝宝不配合 | `Shoes on.` | 穿鞋啦 | 指着鞋子说，给一个明确的下一步。 |

每个临时小禾回应包含一个主推短语和最多两个备选。第一个回应必须足够短，让疲惫的家长能立即说出。

## 4. Variant A: Plan-led V23 基线

### 4.1 页面结构（从上到下）

1. 暖色问候，包含宝宝上下文和轻量日标记。
2. 今日路线 pill，例如 `照护场景 · 睡前收玩具`。
3. 主今日短语卡片：英文短语、中文释义、音频图标、主 CTA。
4. 小禾内联说明：解释为什么这句适合今天。
5. 轻活动建议：与短语相关的三个小活动。
6. 花园痕迹预览：安静的完成回响。
7. 静态底部导航提示：首页 / 发现 / 花园 / 我。

### 4.2 交互状态

**默认计划态：**

- 主 CTA：`开始练一句`
- 次要动作：`换个眼前场景` 打开临时小禾状态

**练习完成态：**

- 主卡片变为完成状态
- CTA 变为 `再说一次` 和 `下一句稍后再来`
- 花园痕迹预览显示新的小标记
- 小禾给出一句以家长为中心的反馈

**临时场景态：**

- 选中的场景替换路线 pill 和主短语内容
- 可见的返回动作恢复今日计划
- 文案明确说明这是一次性帮助路径，不是今日计划的替代

### 4.3 视觉策略

A 应该平静、清晰、低风险。使用现有 Warm Paper Kindness 语言：暖纸背景、克制卡片、清晰 CTA、英文短语突出，没有课程仪表盘感觉。

## 5. Variant B: Scene-mentor 方向

### 5.1 页面结构（从上到下）

1. 亲子时刻标题，例如 `今晚 3 分钟，陪宝宝收个尾`。
2. 小禾存在感：作为与当前时刻关联的小导师气泡。
3. 场景卡片：家长动作先行，短语嵌入场景中。
4. 主 CTA：`试着说这一句`。
5. 快速场景救援行：`宝宝不肯睡`、`洗澡哭了`、`要出门了`。
6. 练习后的温柔结果回响：家长刚才做了什么，今晚可以怎么复用。
7. 花园痕迹预览：作为次级情感反馈。
8. 静态底部导航提示：首页 / 发现 / 花园 / 我。

### 5.2 交互状态

**默认计划态：**

- 家长先看到具体照护时刻，再看到进度指标
- 小禾把短语框定为"现在就能用的"，而不是一个课程单元

**练习完成态：**

- 标题变为 `刚刚完成一次亲子英语时刻`
- 小禾确认这个动作的价值
- 花园痕迹安静生长，不抢焦点

**临时场景态：**

- 快速场景行打开小禾建议面板或内联展开状态
- 小禾返回一个主推短语加可选备选
- 动作：`练这句`、`换个更温柔的说法`、`回到今日计划`

### 5.3 视觉策略

B 应该感觉更像育儿伴侣，而不是课程首页。屏幕应该先引导生活上下文，再是短语，再是进度。小禾应该感觉存在但不主导。视觉温暖来自间距、柔和层级和有用文案，而非装饰性儿童元素。

## 6. 临时场景交互定义

临时场景是用户在非推荐场景下快速获取小禾帮助的路径。A 和 B 变体共享以下交互定义。

**触发方式：**

- A 变体：点击次要动作 `换个眼前场景`
- B 变体：点击快速场景救援行中的场景 chip

**面板形式：**

- 底部弹出面板（bottom sheet），与 Shell V2 设置面板风格一致。

**面板内容：**

1. 小禾头部：`现在想说什么场景？`
2. 快捷 chip 列表：横向可滚动，展示常见临时场景（宝宝不肯睡、洗澡哭了、要出门了等）。
3. 用户输入框：`自己说说看`，支持手写场景描述。
4. 主 CTA：`帮我一句`

**小禾回应：**

1. 返回一个主推短语 + 最多两个备选短语。
2. 备选短语以横向可滚动 chip 形式展示。
3. `换个更温柔的说法`：触发重新请求，LLM 使用更柔和的语气参数重新生成。
4. 每个回应包含中文释义和小禾使用提示。

**进入练习：**

1. 点击主推短语或备选 chip → 进入临时场景练习。
2. 练习页保留临时来源标签（如 `临时 · 宝宝不肯睡`）。
3. 完成后按临时场景归因到花园痕迹。

**关闭面板：**

1. 下滑关闭或点击关闭按钮。
2. 关闭后回到原来的 Home 上下文（A 的默认计划态或 B 的亲子时刻情境）。
3. 临时场景不替换今日推荐，不改变今日路线。

## 7. A/B 关键差异对比

| 维度 | A: Plan-led | B: Scene-mentor |
|------|-------------|-----------------|
| 首屏锚点 | 今日短语卡片 | 亲子时刻情境 |
| 小禾存在 | 内联说明 + 问小禾按钮 | 导师气泡 + 场景建议行 |
| 短语呈现 | 独立卡片，突出英文 | 嵌入场景描述中 |
| CTA 文案 | `开始练一句`（任务导向） | `试着说这一句`（行动导向） |
| 临时场景 | 通过"换个眼前场景"进入 | 快速救援行常驻可见 |
| 完成反馈 | 主卡片状态变化 + 花园 | 情感确认 + 花园 |
| 信息层级 | 短语 > 活动 > 花园 | 情境 > 短语 > 行动 > 痕迹 |

## 8. 用户测试脚本

A 和 B 使用相同任务。测试者之间平衡顺序。

| 任务 | 指令 | 预期行为 |
|------|------|---------|
| Task 1 | 打开 Home，不解释，问测试者觉得今天应该做什么。 | 3 秒内识别推荐动作 |
| Task 2 | 让他们完成一句短语并返回 Home。 | 无需口头指导完成 |
| Task 3 | 问完成后发生了什么变化，反馈是否有意义。 | 能解释变化 |
| Task 4 | 给一个临时场景：`宝宝不肯睡，你现在想马上说一句英语安抚他。` 让他们找小禾帮忙。 | 30 秒内找到并获得可说建议 |
| Task 5 | 问哪个版本更像他们真实育儿时会打开的。 | 给出偏好理由 |

## 9. 验收标准

只有当一个变体满足以下门槛时，才能从浏览器原型进入 Flutter + QA-backend 测试：

1. 至少 80% 测试者无需口头指导完成一句并返回 Home。
2. 至少 70% 能解释完成短语后 Home 的变化。
3. 5 个测试者中不超过 1 个在默认态问"我现在该做什么？"
4. Quick Ask 从发现入口到获得可说建议不超过 30 秒。
5. 测试者把小禾描述为有帮助的亲子英语导师，而不是通用聊天机器人。
6. 测试者在注意到花园或进度细节之前就能识别主推短语。
7. 被选中的视觉方向被描述为温暖、可用、面向家长，而不是幼稚或课程感重。

## 10. 推荐 B 方向的设计理由

### 10.1 产品层面

- B 更好地验证 Phase 1 的核心承诺：在真实育儿时刻中使用英语。
- B 把"生活场景 → 英文短语 → 行动"的信息流对齐了家长的认知路径。
- B 的快速场景救援行降低了临时求助的摩擦，这对疲惫家长至关重要。

### 10.2 交互层面

- B 的"情境先行"结构让家长先产生共鸣，再看到要做的事。
- B 的 CTA "试着说这一句"比"开始练一句"更贴近真实行为——家长不是在"练习"，而是在"说"。
- B 的临时场景入口常驻可见，不需要先理解页面结构才能找到。

### 10.3 视觉层面

- B 通过情境标题和导师气泡建立陪伴感，而不是通过装饰元素。
- B 的信息层级更接近"有人在帮你安排"，而不是"自己看课程表"。
- B 在完成态的情感反馈更强，有助于建立"说了一句 → 有意义"的因果。

### 10.4 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| B 的情境标题可能被忽略 | 标题使用暖橙色强调词，确保首屏可见 |
| 快速救援行占用空间 | 救援行使用紧凑 chip 设计，可横向滚动 |
| 小禾气泡可能感觉多余 | 气泡文案与场景强关联，不显示通用提示 |
| 完成反馈可能过度情感化 | 保持克制，只确认事实，不做夸张庆祝 |

## 11. 实现注意事项

### 11.1 原型实现

- 使用浏览器可点击原型，本地静态状态。
- 支持 A 和 B 的并排评估，使用相同任务脚本和相同内容数据。
- 不调用 API。QA backend 使用在设计通过浏览器测试并进入 Flutter 用户级测试后才开始。

### 11.2 状态模型

```
variant: 'plan-led' | 'scene-mentor'
homeState: 'defaultPlan' | 'practiceComplete' | 'temporaryScene'
selectedScene: 默认照护场景 | 临时小禾场景
practiceResult: 空 | 一个完成短语摘要
```

## 12. 对齐 DESIGN.md

原型必须对齐 Warm Paper Kindness 设计系统：

- 主背景：`#FFF8F0`
- 主 CTA：`#FF8C42`
- 英文短语高亮：`#3B8577`
- 英文柔和背景：`#D4E8E3`
- 英文短语字体：Fraunces
- 英文 UI 字体：DM Sans
- 中文字体：PingFang SC / Noto Sans SC / Microsoft YaHei
- 不使用 emoji、花哨动效或装饰性渐变
- 阴影克制，移除阴影后页面仍有清晰层级
