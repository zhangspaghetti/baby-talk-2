# Flutter Mobile Garden 花园页交互结论

日期：2026-05-28
状态：Garden 子设计已确认（待合入整体 QA 迭代设计）

## 1. 读者与读完后动作

本文件写给产品、设计和 Flutter 实现工程师。

读完后，读者应该能够：

1. 判断 Garden 页和 Home 花园痕迹摘要的职责边界。
2. 按 Garden 的信息架构实现 Flutter 花园页。
3. 为加载、空态、离线等状态设计用户可见反馈。
4. 验收花园页是否符合 `DESIGN.md` 的 Warm Paper Kindness 方向。

本文件不是实现计划，也不直接批准生产代码改动。进入实现前仍需要拆分任务、确认数据契约和测试范围。

## 2. 背景与目标

Home V23 的花园痕迹只是轻摘要入口，用户完成一句后能看到"今日痕迹 / 小芽"。但花园本身需要承载更完整的练习历史和成长感，让家长看到自己真正说过的话、在什么场景下说的、留下了什么样的痕迹。

Garden 的定位是"真实练习的生长花园"：家长在这里看到的不是数据仪表盘，而是一片由自己真实练习长出来的花园。

目标：

1. 花园展示真实练习痕迹，不是打卡记录。
2. 每一条痕迹都保留完整的上下文：说了什么、在什么场景、宝宝反应如何。
3. 花园的成长感来自"说过的句子越来越多"，不是分数或等级。
4. 视觉设计温暖、克制，像一个安静的花园，不像数据报告。
5. 与 Home 的花园痕迹摘要自然衔接。

非目标：

- 不做游戏化元素：没有分数、等级、排行榜、连续天数。
- 不做复杂的花园动画或可交互花圃地图。
- 不做社交分享或对比功能。
- 不把花园做成学习进度仪表盘。
- 不使用 emoji 或儿童化装饰。

## 3. 页面职责边界

Home 花园痕迹摘要承载：今日是否有新痕迹、最新一条痕迹预览、进入花园的入口。

Garden 完整页面承载：

1. 所有历史练习痕迹的完整列表。
2. 每条痕迹的详细上下文（英文句子、中文释义、场景、宝宝反应、时间）。
3. 按时间倒序的练习日历。
4. 简单的场景分布统计。
5. 从痕迹回到对应场景的入口。

关键边界：Home 花园摘要是"今天有新痕迹吗"，Garden 完整页面是"我到底说过哪些话"。

## 4. 信息架构

花园页首屏优先级：

1. 页面标题和花园状态轻提示。
2. 最近练习痕迹列表。
3. 按日分组的时间线。
4. 底部场景分布轻摘要。

结构：

```text
顶部栏
  返回 / 花园

花园状态
  你的花园里有 N 条真实练习痕迹。

最近痕迹
  今天
    喂饭时说过 "One more bite."
      再吃一口 · 宝宝有回应了 · 10:23
    睡前说过 "Let's put it back."
      我们把它放回去吧 · 宝宝安静了 · 09:15
  昨天
    洗澡时说过 "Water is warm."
      水是暖的 · 宝宝配合了 · 20:45
    出门时说过 "Shoes on."
      穿鞋子 · 没反应 · 18:30

场景分布
  喂饭 8 句 · 洗澡 5 句 · 睡前 12 句 · 出门 3 句
```

设计要求：

1. 痕迹列表是页面主体，不被统计图表挤压。
2. 每条痕迹保留完整上下文，不只显示句子。
3. 按日分组，每天有清晰的视觉分隔。
4. 场景分布放在底部作为轻补充，不是主内容。
5. 页面底部留足安全区空间，不被底部导航遮挡。

## 5. 痕迹条目设计

每条痕迹是一个完整的练习记录，不是一个打卡勾。

条目内容：

1. 场景标签（如"喂饭"、"睡前"、"出门"）。
2. 英文短语（使用 Fraunces 字体，--english 颜色）。
3. 中文释义（小号辅助文字）。
4. 宝宝反应（如有记录：有回应 / 安静了 / 没反应 / 配合了 / 吃了一口 / 喝了一口）。
5. 时间（如"10:23"）。
6. 来源标记（今日推荐 / 小禾临时建议）。

条目状态：

1. 正常态：完整信息可见。
2. 今日痕迹：使用 --english-soft 背景轻微高亮，与 Home 花园摘要的"小芽"呼应。
3. 临时场景痕迹：保留场景标签，不统一显示为"临时"。

设计要求：

1. 每条痕迹占据合理高度，不挤压为紧凑列表。
2. 英文短语是条目中最醒目的文字。
3. 宝宝反应使用温和的语义颜色，不做强视觉标记。
4. 场景标签使用 pill 样式，与 Home 和 Practice 的场景标签一致。
5. 条目之间有清晰但不重的分隔。
6. 临时场景痕迹和推荐痕迹视觉权重一致，不降级显示。

## 6. 时间分组

痕迹按日分组，从最近一天开始倒序。

分组规则：

1. 今天：显示"今天"标题，不显示日期。
2. 昨天：显示"昨天"标题。
3. 更早：显示完整日期，如"5月26日"。
4. 每天的痕迹按时间倒序排列（最新的在最上面）。

设计要求：

1. 日期标题使用 --text-secondary 颜色，不抢痕迹条目的视觉权重。
2. 日期标题与第一条痕迹之间有合理间距。
3. 不同日期之间有清晰的视觉分隔。
4. 当某天只有一条痕迹时，仍然显示日期标题。

## 7. 场景分布

场景分布是花园底部的轻摘要，不是主内容。

内容：

1. 横向排列的场景统计条目。
2. 每个条目包含场景名和该场景下的痕迹数量。
3. 使用 pill 或轻标签样式。

展示规则：

1. 只显示有痕迹的场景，不显示空场景。
2. 按痕迹数量降序排列。
3. 不显示百分比或进度条。
4. 点击场景条目可筛选该场景的痕迹（可选功能，Phase 1 可不做）。

设计要求：

1. 场景分布区域使用 --bg-sunken 背景，与主列表形成轻层级。
2. 不使用图表、柱状图或饼图。
3. 数字使用 DM Sans 的 tabular-nums 特性。
4. 整体区域不高于 80px，保持轻量。

## 8. 空态

首次进入花园或尚无练习痕迹时的空态。

空态内容：

1. 花园图标或轻插画（不使用 emoji）。
2. 主文案：`你的花园还很安静。`
3. 辅助文案：`说完今日短语后，这里会记下你的第一条真实练习痕迹。`
4. 主按钮：`回到首页说一句`

设计要求：

1. 空态居中显示，不偏上或偏下。
2. 不使用鼓励性过强的文案（如"快来种一朵花吧"）。
3. 主按钮使用 --accent 颜色，与 Home 的主 CTA 一致。
4. 空态不显示场景分布区域。

## 9. 加载态与离线态

加载态：

1. 保留顶部导航栏。
2. 痕迹列表区域显示暖纸骨架屏。
3. 骨架屏使用 --bg-sunken 颜色的矩形条，模拟痕迹条目高度。
4. 不显示空白区域或加载 spinner。

离线态：

1. 花园数据来自本地缓存，不阻断浏览。
2. 顶部显示轻提示：`离线时看到的是上次同步的痕迹。`
3. 痕迹列表正常展示缓存数据。
4. 不显示错误或重试入口。

## 10. 与 Home 花园摘要的衔接

Home 花园摘要（"今日痕迹 / 小芽"）是花园页的入口之一。

衔接规则：

1. Home 完成一句后，花园摘要展开显示最新痕迹预览。
2. 点击花园摘要或底部导航"花园"Tab 进入完整花园页。
3. 花园页打开后，如果有今日新痕迹，最新一条使用 --english-soft 背景高亮。
4. 花园页的痕迹数据与 Home 摘要共享同一数据源。

设计要求：

1. 花园页的痕迹条目样式与 Home 摘要的预览样式保持视觉一致。
2. Home 摘要的"小芽"概念在花园页通过今日高亮条目延续。
3. 不做复杂的页面转场动画，保持轻量过渡。

## 11. 视觉系统要求

Garden 必须对齐 `DESIGN.md`。

字体：

1. 英文短语使用 Fraunces（24px 以上）。
2. 中文 UI 使用 PingFang SC / Noto Sans SC / Microsoft YaHei。
3. 英文 UI 使用 DM Sans。
4. 数字使用 DM Sans 的 tabular-nums 特性。

颜色：

1. 主背景：`#FFF8F0`（--bg-base）。
2. 痕迹条目背景：`#FFFFFF`（--bg-surface）。
3. 今日痕迹高亮背景：`#D4E8E3`（--english-soft）。
4. 英文短语：`#3B8577`（--english）。
5. 场景标签：`#FFF0E5` 背景 + `#FF8C42` 文字（--accent-light / --accent）。
6. 宝宝反应：`#6B8F5E`（--success）用于正面反应，`#8A7D76`（--text-muted）用于"没反应"。

视觉要求：

1. 不使用紫色、蓝紫渐变或儿童教育类高饱和配色。
2. 不使用 emoji 作为设计元素。
3. 不使用大面积装饰光斑或渐变。
4. 卡片只在承载真实内容时使用。
5. 阴影应克制（--shadow-sm 级别），移除阴影后页面仍应有清晰层级。
6. 场景标签使用 pill 样式（--radius-full），与全局场景标签一致。
7. 日历分组标题使用轻字重，不抢痕迹条目视觉重心。

## 12. 响应式与可访问性

小屏优先级：

1. 320/360 宽度下，痕迹条目保持完整信息，英文短语不截断。
2. 场景分布可以换行显示，不强制单行。
3. 不允许横向滚动。
4. 主要按钮不小于 44px，推荐 48px。

可访问性要求：

1. 痕迹条目有清晰语义（场景、短语、反应、时间）。
2. 宝宝反应不能只依赖颜色表达，需要有文字标签。
3. 场景分布的数字需要有关联的文字说明。
4. 空态按钮有清晰语义。
5. 支持 TalkBack/VoiceOver 基础路径测试。
6. 支持减少动画设置。

## 13. 后续实现提示

实现 Garden 时需要重点关注：

1. 花园数据来自本地 Isar 数据库，需要定义痕迹数据模型。
2. 痕迹数据模型应包含：英文短语、中文释义、场景标签、宝宝反应、时间戳、来源（推荐/临时）。
3. Home 花园摘要和 Garden 完整页面共享同一数据源。
4. 场景分布统计需要实时计算，不做缓存。
5. 加载态骨架屏需要模拟真实痕迹条目的高度和布局。
6. 离线态需要依赖本地缓存，不调用远程接口。
7. 字体资源需要按 `DESIGN.md` 打包，不依赖 Google Fonts CDN。
8. 底部导航安全区需要正确处理，避免痕迹列表被遮挡。

建议实现任务：

1. 定义花园痕迹 Isar 数据模型。
2. 实现痕迹列表的时间分组和倒序排列。
3. 实现场景分布统计。
4. 实现空态、加载态和离线态。
5. 接入 Home 花园摘要的数据共享。
6. 验证 320、360、430 宽度，以及 TalkBack/VoiceOver 基础路径。

## 14. 已确认视觉原型

最终确认原型：

- `qa-mobile-garden-v1-warm-garden.html`

关键调整：

1. 花园从游戏化花圃地图改为真实练习痕迹列表。
2. 痕迹条目保留完整上下文，不只显示句子。
3. 按日分组的时间线，不是按场景分组。
4. 场景分布作为底部轻摘要，不是主内容。
5. 空态文案克制，不做鼓励性引导。
6. 今日痕迹使用轻高亮，与 Home "小芽"概念呼应。
7. 宝宝反应使用温和语义颜色，不做强视觉标记。
8. 字体和颜色对齐 `DESIGN.md`。

## 15. 本轮不包含

本文件不定义以下内容：

1. 花园与后端同步的接口契约。
2. 痕迹删除或编辑功能。
3. 场景筛选交互（Phase 2 可选）。
4. 花园分享功能。
5. 复杂的花园动画或可交互花圃地图。
6. 成长页的数据指标和图表。

这些内容需要在对应子设计或实现计划中继续确认。
